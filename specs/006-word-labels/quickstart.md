# Quickstart: проверка меток слов

## Предварительно

```bash
yarn setup
uv run --directory backend alembic upgrade head   # создаст labels и word_labels
yarn dev
```

## Автоматические проверки

```bash
yarn test:api
yarn typecheck
yarn build
uv run --directory backend ruff check app tests
```

Тесты в `backend/tests/test_api.py` (таблично, где возможно). Контракт —
[contracts/api.md](./contracts/api.md), правила — [data-model.md](./data-model.md).

| Что проверяем | Требование |
|---|---|
| `POST /words` с `labels: ["Посуда", "кухня"]` при существующей «Кухня» → у слова «Кухня» и новая «Посуда», в ответе сразу по алфавиту; в списке меток две | FR-001, FR-004, FR-004a |
| `POST /words`-дубль (409) с новой меткой → метка не создана | FR-004a |
| `PATCH /words/{id}` без `labels` не меняет метки; с `[]` снимает все; с новым набором заменяет | FR-003a |
| `PATCH /words/{id}`, приводящий к дублю (409), не меняет метки и не создаёт новых | FR-003a |
| `labels: ["кухня", "КУХНЯ ", "кухня"]` → одна метка на слове | FR-002 |
| Пустое название и название из 51 символа → 422 (в слове и в `/labels`) | FR-010 |
| `GET /words?label=<id>`, `?label=none`, сочетание с `search` и `status`; `?label=abc` → 422; неизвестный id → `total: 0` | FR-007, FR-008 |
| `GET /labels` упорядочен по названию без учёта регистра, «ёлка» между «ежевика» и «ягода», `word_count` верный | FR-009 |
| `POST /labels` дубль по регистру → 409 | FR-011 |
| `PATCH /labels/{id}`: переименование видно в `GET /words`; занятое другой меткой → 409; смена регистра своей → 200 | FR-011, FR-012, SC-003 |
| `DELETE /labels/{id}` снимает метку со слов; число строк `words`, `progress`, `review_log` прежнее | FR-013, FR-014, SC-004 |
| `DELETE /words/{id}` удаляет связки, метка остаётся | FR-015 |
| Правка меток и смена статуса (в т.ч. возврат в «Новое») не пишут в `review_log` и не меняют метки / прогресс соответственно | FR-005, SC-004 |
| `mode=learn` и `mode=review` отдают тот же набор слов с метками и без | SC-006 |

В `backend/tests/test_import.py`: повторный импорт сохраняет связки у существующей
строки и не создаёт меток (FR-016).

## Ручные сценарии

1. **Метки при добавлении.** «Добавить слово» → `knife` / «нож», в поле меток ввести
   «кухня» → «Создать метку «кухня»», затем «инструменты» → создать. «Добавить»:
   в словаре у `knife` две метки.
2. **Дубль не оставляет следов.** Добавить `knife` / «нож» ещё раз с новой меткой
   «тест»: сообщение о дубле, введённое и выбранные метки на месте. В «Настройки →
   Метки» метки «тест» нет.
3. **Правка.** В строке `knife` меток не поменять без «Изменить». «Изменить» → снять
   «инструменты» → «Отмена»: метки прежние. Снова «Изменить» → снять → «Сохранить»:
   осталась «кухня».
4. **Подсказки.** В поле меток ввести «КУХ»: подсказана «кухня», пункта «Создать» нет,
   если введено «Кухня» целиком.
5. **Фильтр.** Дать «кухня» трём словам. В словаре выбрать «кухня» — три слова;
   добавить поиск — одно. Выбрать «Без меток» — среди результатов нет размеченных.
6. **Вкладка «Метки».** «Настройки» → «Метки» (`/settings?tab=labels`): метки по
   алфавиту с числом слов. Создать «кухяня»; создать «Кухня» → сообщение о дубле.
   Переименовать «кухяня» → «посуда». Перезагрузка оставляет открытой вкладку.
7. **Удаление.** Удалить «кухня»: подтверждение называет 3 слова. «Отмена» — всё на
   месте. Подтвердить — у слов метки нет, их статусы прежние. Если в словаре был
   выбран фильтр «кухня», он сбрасывается на «Все метки».
8. **Много меток.** Дать слову 6 меток: строка словаря переносит их и не уходит за
   край на ширине 375 px.
9. **Занятия не изменились.** «Учить слова» и «Повторить слова» берут те же слова, что
   до разметки.
