# Data Model: Метки слов

## Новые таблицы

### `labels` — метка

| Колонка | Тип | Ограничения | Смысл |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `name` | VARCHAR(50) | NOT NULL | Название как ввёл пользователь, без крайних пробелов |
| `name_key` | VARCHAR(50) | NOT NULL, UNIQUE (`ux_labels_name_key`) | `name.strip().casefold()` — ключ уникальности; сортировка — по нему же с «ё» → «е» (R2, R6) |
| `created_at` | DATETIME | NOT NULL, default `utcnow()` | naive UTC, как у остальных таблиц |

Метка существует независимо от слов: у неё может не быть ни одной связки.

### `word_labels` — связка «слово — метка»

| Колонка | Тип | Ограничения |
|---|---|---|
| `word_id` | INTEGER | FK → `words.id` ON DELETE CASCADE, часть PK |
| `label_id` | INTEGER | FK → `labels.id` ON DELETE CASCADE, часть PK |

- PK `(word_id, label_id)` — одна метка на слове не больше одного раза (FR-002).
- Индекс `ix_word_labels_label_id (label_id)` — фильтр по метке и счётчик (R5).
- Каскады: удаление слова снимает его метки (FR-015), удаление метки снимает её
  со всех слов (FR-014). Сами `words`, `progress`, `review_log` при этом не
  меняются.

## Изменения ORM

- `Label` — модель `labels`.
- `Word.labels: list[Label]` — `relationship(secondary="word_labels",
  lazy="selectin", order_by=func.replace(Label.name_key, "ё", "е"))` — порядок по
  названию без учёта регистра, «ё» = «е»; совпадает с `label_sort_key` в Python (R6).
- `Label.words` не заводится: обходить слова от метки нужно только в фильтре и
  счётчике, а это запросы, а не навигация по объектам (Принцип V).
- `WordStatus`, `Progress`, `ReviewLog`, `Setting` не меняются.

## Правила валидации

| Правило | Где проверяется | Ответ |
|---|---|---|
| Название после обрезки — 1…50 символов | Pydantic (`LABEL_NAME_MAX = 50`) | 422 |
| Название свободно по `name_key` при создании | `POST /labels` | 409 «Метка «…» уже есть» |
| При переименовании ключ занят **другой** меткой | `PATCH /labels/{id}` | 409; смена только регистра — 200 (R8) |
| Метка не найдена | `PATCH`/`DELETE /labels/{id}` | 404 |
| Элемент `labels` в форме слова пуст или длиннее 50 | Pydantic | 422 |
| Слово-дубль при сохранении с метками | `_same_meaning` до разрешения меток | 409, метки не создаются, транзакция откатывается (FR-003a, FR-004a) |

## Разрешение списка названий в форме слова (R3)

Вход — `labels: list[str]` из `WordCreate`/`WordUpdate`.

1. Обрезать каждое название; повторы по `casefold` схлопнуть, первое вхождение
   побеждает.
2. Для каждого ключа найти метку по `name_key`; найденная берётся со своим
   написанием.
3. Для ненайденных создать `Label(name, name_key)`.
4. Отсортировать итоговый список по `label_sort_key` — ответ на `POST`/`PATCH`
   отдаёт присвоенный список как есть, без перечитывания из базы (R4).
5. `word.labels = <итоговый список>` — ORM сам удалит и добавит строки
   `word_labels`.

Всё выполняется в сессии запроса; сохранение фиксирует `get_session`, исключение
откатывает. В `PATCH` поле `labels` отсутствует → шаги не выполняются, метки слова
прежние.

## Инварианты, которые закрепляют тесты

- Изменение меток слова не создаёт строк `review_log` и не меняет `progress`
  (FR-005, SC-004).
- Удаление метки не меняет число строк `words`, `progress`, `review_log`.
- Смена статуса слова, включая возврат в «Новое», не меняет его метки.
- Повторный импорт не меняет `labels` и `word_labels` (FR-016).
