# API Contract: порядок новых слов и отметка «Учить первым»

Все маршруты под `/api`. Ошибки — с человекочитаемым `detail` на русском.

## Настройки

### `GET /api/settings`

```json
{ "new_words_order": "oldest_first" }
```

Без сохранённого значения — `oldest_first`.

### `PUT /api/settings`

Запрос и ответ — тот же объект:

```json
{ "new_words_order": "newest_first" }
```

| Ситуация | Ответ |
|---|---|
| Значение из перечисления | 200, сохранённые настройки |
| Неизвестное значение или поле пропущено | 422 |

Настройка действует с ближайшего отбора новых слов; уже отданные занятия не
меняются (FR-006). В `review_log` ничего не пишется.

## Слова

### `WordOut` / `WordWithProgress` — новое поле

```json
{ "id": 42, "word": "roll out", "translation": "внедрить", "...": "...", "priority": false }
```

### `GET /api/words?search=&status=&priority=&limit=&offset=`

`priority=true` оставляет только отмеченные слова и сочетается с `search` и
`status`. Без параметра или `priority=false` — фильтра нет. Сортировка списка не
меняется (по `id`).

### `PUT /api/words/{id}/priority`

```json
{ "priority": true }
```

| Ситуация | Ответ |
|---|---|
| Слово новое, `priority: true` или `false` | 200, `WordWithProgress` с новым значением |
| Слово не новое, `priority: false` | 200, ничего не меняется (отметки у такого слова нет) |
| Слово не новое, `priority: true` | 409, `detail`: «Поднять можно только новое слово» |
| Слова нет | 404 |

Повторный запрос с тем же значением — не ошибка. `review_log`, `ease` и `lapses`
не меняются (FR-014).

### Побочное действие существующих маршрутов

`PUT /api/words/{id}/status` с любым статусом, кроме `new`, снимает отметку:
в ответе `priority: false`.

## Изучение

Формат ответов не меняется, меняется только то, какие слова в них попадают.

- `GET /api/study/session?mode=learn`, `GET /api/study/new`: новые слова в порядке
  «сначала поднятые, затем остальные», внутри групп — по `new_words_order`.
  Размер — `min(лимит занятия, остаток дневного лимита)`, как раньше.
- `POST /api/study/select`: `replacement` берётся по тому же правилу. Слово из
  `word_id` после ответа имеет прогресс и `priority: false`.
- `GET /api/study/session?mode=review`: без изменений, порядок по сроку.
