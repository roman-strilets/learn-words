# Feature Specification: Автоматическая разметка слов по меткам

**Feature Branch**: `007-auto-label-classification`

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "надо добавить автоматическую классификацию по меткам. чтобы можно нажать кнопку и все слова были разбиты, если можно, по меткам, но при этом, если метки не подходят, то ничего не добавлять к слову. для этого надо использовать typesafe-sdk (пример: `Choice` с категориями-критериями и вариантом «None of the above», один запрос `system_one` на пачку слов, `TypeSafeClient(timeout=120)`). переменные окружения примера: `TYPESAFE_BASE_URL=http://localhost:11434`, `TYPESAFE_API_KEY=ollama`, `TYPESAFE_DEFAULT_MODEL=nimble` — надо эти переменные захардкодить или вынести в настройки во фронт. т.к. классификация достаточно тяжёлая задача, надо предусмотреть разбиение на этапы. причём, чтобы пользователь сам мог это делать, а не только приложение"

## Clarifications

### Session 2026-10-01

- Q: Когда найденные метки попадают на слова? → A: Сразу, пачка за пачкой, без
  отдельного просмотра; ошибочные метки снимаются вручную.
- Q: Сколько меток может получить слово за один прогон? → A: Не больше одной — самую
  подходящую из набора, либо ни одной.
- Q: Нужно ли метке описание для разметки? → A: Да, необязательное; оно задаётся на
  вкладке «Метки» и служит разметке критерием, без него используется название.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Разложить словарь по меткам одной кнопкой (Priority: P1)

У пользователя тысячи слов и несколько меток: «кухня», «тело», «растения». Размечать
слова по одному в форме «Изменить» долго. Он нажимает «Разметить автоматически», и
приложение само ставит каждому слову самую подходящую метку из списка. Слово, которому
ни одна метка не подходит (`democracy`, `bicycle` при метках «кухня», «тело»,
«растения»), остаётся как было — приложение ничего к нему не добавляет. Уже стоящие
на слове метки никогда не снимаются.

**Why this priority**: Это суть просьбы: заменить ручную разметку тысяч слов одним
действием.

**Independent Test**: Завести метки «кухня», «тело», «растения». Взять слова `spoon`,
`elbow`, `oak`, `kettle`, `knee`, `tulip`, `bicycle`, `democracy`. Запустить разметку:
`spoon` и `kettle` получают «кухня», `elbow` и `knee` — «тело», `oak` и `tulip` —
«растения», у `bicycle` и `democracy` меток не появляется.

**Acceptance Scenarios**:

1. **Given** в словаре есть метки и слова, **When** пользователь запускает
   автоматическую разметку, **Then** каждому обработанному слову, к которому подходит
   одна из меток, эта метка добавляется.
2. **Given** слову не подходит ни одна из меток, **When** разметка обработала его,
   **Then** у слова не появляется ни одной новой метки.
3. **Given** у слова уже есть метки, **When** разметка обработала его, **Then** ни
   одна прежняя метка не снята, а метка, которая уже стоит, не добавляется второй раз.
4. **Given** слово в любом статусе, **When** разметка добавила ему метку, **Then**
   статус, расписание, ease, число ошибок и журнал ответов слова не изменились.
5. **Given** разметка завершена, **When** пользователь смотрит итог, **Then** он видит,
   сколько слов обработано, сколько получили метку (по каждой метке) и сколько
   осталось без новой метки.
6. **Given** в словаре нет ни одной метки, **When** пользователь открывает
   автоматическую разметку, **Then** запуск недоступен, а приложение объясняет, что
   сначала нужно завести метки.
7. **Given** разметка обработала пачку, **When** пачка завершилась, **Then** найденные
   метки уже стоят на словах этой пачки без отдельного подтверждения и видны в
   словаре после обновления списка.
8. **Given** слову подходят две метки из набора (`knife` — «кухня» и «инструменты»),
   **When** разметка обработала его, **Then** слово получает за этот прогон ровно
   одну, самую подходящую.

### User Story 2 — Разметка по этапам (Priority: P1)

Классификация тяжёлая: тысячи слов не обработать одним запросом. Приложение само
делит работу на небольшие пачки и обрабатывает их по очереди, показывая прогресс.
Пользователь тоже может разбить работу на этапы сам: выбрать, какие слова размечать
сейчас (например, только «Без меток», только «Изучается», только первые 200 слов
выборки или начиная с определённого слова), какие метки предлагать, и размер пачки.
Запущенную разметку можно остановить: всё, что уже обработано, остаётся на словах, а
приложение говорит, с какого слова продолжить в следующий раз.

**Why this priority**: Без этапов кнопка «разметить всё» на 7 000 словах либо
упирается в ожидание, либо теряет всю работу при сбое. Пользователь прямо попросил,
чтобы этапами мог управлять он сам.

**Independent Test**: Выбрать фильтр «Без меток», ограничить выборку 40 словами, размер
пачки 10. Запустить: прогресс идёт 10 → 20 → 30 → 40. Остановить после второй пачки:
у первых 20 слов результат сохранён, приложение сообщает слово, с которого продолжить.
Запустить снова, начиная с этого слова: обрабатываются оставшиеся.

**Acceptance Scenarios**:

1. **Given** выборка больше размера пачки, **When** пользователь запускает разметку,
   **Then** приложение обрабатывает слова последовательными пачками и после каждой
   показывает, сколько слов из выборки уже обработано.
2. **Given** пользователь выбирает слова для разметки, **When** он задаёт фильтры (по
   статусу, по метке, включая «Без меток», по поиску) и ограничение числа слов,
   **Then** разметка обрабатывает только слова, удовлетворяющие всем условиям, не
   больше заданного числа, и до запуска показывает, сколько слов попадёт в этап.
3. **Given** пользователь хочет продолжить прошлый этап, **When** он указывает слово,
   с которого начать, **Then** обрабатываются только слова выборки, идущие в
   словаре начиная с него.
4. **Given** в списке меток их больше, чем нужно сейчас, **When** пользователь снимает
   часть меток из набора для разметки, **Then** слова раскладываются только по
   оставшимся меткам, а остальные метки не предлагаются ни одному слову.
5. **Given** разметка идёт, **When** пользователь нажимает «Остановить», **Then**
   новая пачка не начинается, результаты завершённых пачек остаются на словах, а
   приложение показывает слово, с которого продолжить.
6. **Given** пачка завершилась ошибкой (сервис классификации недоступен, не ответил
   вовремя), **When** ошибка произошла, **Then** разметка останавливается, результаты
   прежних пачек сохранены, слова сбойной пачки не изменены, а пользователь видит
   понятное сообщение и слово, с которого продолжить.
7. **Given** пользователь задал размер пачки, **When** он запускает разметку в
   следующий раз, **Then** размер пачки и набор фильтров по умолчанию такие же, как в
   прошлый раз.

### User Story 3 — Настройки подключения к классификатору (Priority: P2)

Разметку выполняет языковая модель, доступная по сети (по умолчанию — локальная, на
`http://localhost:11434`, ключ `ollama`, модель `nimble`). Пользователь видит и меняет
адрес, ключ и модель на странице «Настройки», не правя файлы проекта, и может
проверить, что подключение работает, до запуска разметки.

**Why this priority**: С настройками по умолчанию разметка работает сразу, поэтому P1
не зависит от этой истории. Но без неё смена модели или адреса требует правки кода.

**Independent Test**: Открыть «Настройки»: поля заполнены значениями по умолчанию.
Указать несуществующую модель и нажать «Проверить подключение»: понятная ошибка.
Вернуть `nimble`: проверка проходит. Перезагрузить страницу: значения сохранились.

**Acceptance Scenarios**:

1. **Given** пользователь ничего не настраивал, **When** он открывает настройки
   классификатора, **Then** видит адрес `http://localhost:11434`, ключ `ollama` и
   модель `nimble`, и разметка работает с этими значениями.
2. **Given** пользователь изменил адрес, ключ или модель и сохранил, **When** он
   перезагружает страницу или запускает разметку, **Then** действуют новые значения.
3. **Given** пользователь нажимает «Проверить подключение», **When** сервис доступен
   и модель отвечает, **Then** приложение сообщает об успехе; **When** нет, **Then**
   показывает понятную причину (адрес недоступен, модель не найдена, ключ отклонён,
   нет ответа за отведённое время).
4. **Given** пользователь хочет вернуть исходные значения, **When** он нажимает
   «Сбросить», **Then** поля возвращаются к значениям по умолчанию.
5. **Given** метка «кухня» без описания, **When** пользователь на вкладке «Метки»
   задаёт ей описание «предметы на кухне: посуда, приборы, техника» и сохраняет,
   **Then** описание видно у метки, а следующие запуски разметки судят о «кухне» по
   нему; стерев описание, пользователь возвращает разметку к названию.

---

### Edge Cases

- **Метка без описания** («разное», «B2»): разметка судит только по названию и может
  понять его неверно; пользователь уточняет смысл описанием метки.
- **Несколько подходящих меток**: `knife` подходит и к «кухня», и к «инструменты» —
  за прогон слово получает одну; вторую пользователь ставит вручную или повторным
  прогоном с набором без первой метки.
- **Несколько значений одного слова**: каждое значение — отдельная запись; разметка
  учитывает перевод записи, чтобы `bark` «кора» и `bark` «лаять» могли получить
  разные метки.
- **Слово уже стоит с меткой, которую выбрала разметка**: ничего не меняется, в итоге
  слово считается обработанным без новой метки.
- **Метку удалили или переименовали во время разметки**: удалённая метка больше не
  ставится, следующие пачки идут с актуальным списком; слова прошлых пачек не
  пересматриваются.
- **Слово удалили во время разметки**: оно пропускается, разметка не останавливается.
- **Модель вернула ответ не из списка меток** или не ответила по слову: слово
  считается «метка не подошла», ничего не добавляется.
- **Пустая выборка** (фильтры не нашли слов или начальное слово последнее): запуск
  недоступен, приложение объясняет почему.
- **Одна метка в наборе**: разметка работает — каждое слово либо получает её, либо
  остаётся без изменений.
- **Перезагрузка страницы или закрытие вкладки во время разметки**: завершённые пачки
  сохранены, текущая пачка либо применена целиком, либо не применена вовсе;
  продолжить можно с последнего показанного слова.
- **Повторный запуск на тех же словах**: прежние метки не дублируются и не снимаются;
  итог может отличаться, если модель ответит иначе.
- **Импорт словаря**: импорт не запускает разметку и не меняет метки.

## Requirements *(mandatory)*

### Functional Requirements

**Разметка**

- **FR-001**: Пользователь ДОЛЖЕН иметь возможность запустить автоматическую разметку
  слов по меткам одним действием со страницы «Словарь».
- **FR-002**: Разметка ДОЛЖНА выбирать для слова только метки из набора, выбранного для
  этого запуска, либо решать, что ни одна не подходит.
- **FR-003**: Если ни одна метка из набора не подходит слову, разметка НЕ ДОЛЖНА
  добавлять к нему ничего.
- **FR-004**: Разметка НЕ ДОЛЖНА снимать метки со слов и НЕ ДОЛЖНА добавлять слову
  метку, которая на нём уже стоит.
- **FR-005**: При выборе метки разметка ДОЛЖНА учитывать английское слово и его перевод
  в этой записи словаря.
- **FR-006**: За один прогон слово ДОЛЖНО получать не больше одной метки — самую
  подходящую из набора.
- **FR-007**: Найденные метки ДОЛЖНЫ ставиться на слова сразу по завершении каждой
  пачки, без отдельного шага просмотра и подтверждения.
- **FR-007a**: У метки ДОЛЖНО быть необязательное описание (до 200 символов), которое
  пользователь задаёт и меняет на вкладке «Метки» страницы «Настройки»; разметка
  ДОЛЖНА использовать описание как критерий метки, а при его отсутствии — название.
- **FR-008**: Разметка НЕ ДОЛЖНА менять статус, расписание, ease, число ошибок и журнал
  ответов слов и НЕ ДОЛЖНА считаться ответом на упражнение.
- **FR-009**: Метки, добавленные разметкой, ДОЛЖНЫ ничем не отличаться от поставленных
  вручную: их можно снять в форме «Изменить», они участвуют в фильтре и учитываются
  в числе слов у метки.
- **FR-010**: Если в словаре нет ни одной метки, запуск разметки ДОЛЖЕН быть
  недоступен с объяснением причины.

**Этапы**

- **FR-011**: Приложение ДОЛЖНО обрабатывать выборку последовательными пачками
  ограниченного размера; результат каждой пачки ДОЛЖЕН сохраняться до начала
  следующей.
- **FR-012**: Пользователь ДОЛЖЕН иметь возможность задать размер пачки (по умолчанию
  20 слов, от 1 до 100).
- **FR-013**: Пользователь ДОЛЖЕН иметь возможность ограничить выборку слов этапа:
  фильтрами по статусу, по метке (включая «Без меток») и по поиску, максимальным числом
  слов и словом, с которого начать (в порядке словаря). Число слов, попадающих в
  этап, ДОЛЖНО быть видно до запуска.
- **FR-014**: Пользователь ДОЛЖЕН иметь возможность выбрать, какие метки участвуют в
  разметке; по умолчанию участвуют все.
- **FR-015**: Во время разметки ДОЛЖЕН быть виден прогресс: сколько слов этапа
  обработано из скольких, сколько получили метку.
- **FR-016**: Пользователь ДОЛЖЕН иметь возможность остановить разметку; текущая пачка
  либо применяется целиком, либо не применяется, следующая не начинается.
- **FR-017**: После остановки, ошибки или завершения приложение ДОЛЖНО показать итог
  (обработано, получили метку — по каждой метке, остались без новой метки) и слово, с
  которого продолжить, если этап не завершён.
- **FR-018**: Ошибка пачки ДОЛЖНА останавливать разметку с понятным сообщением, не
  затрагивая результаты завершённых пачек и не меняя слова сбойной пачки.
- **FR-019**: Последние выбранные размер пачки и фильтры этапа ДОЛЖНЫ предлагаться по
  умолчанию при следующем запуске.

**Настройки подключения**

- **FR-020**: На странице «Настройки» ДОЛЖНЫ быть поля адреса сервиса классификации,
  ключа доступа и модели со значениями по умолчанию `http://localhost:11434`, `ollama`
  и `nimble`.
- **FR-021**: Изменённые значения ДОЛЖНЫ сохраняться в приложении, действовать после
  перезагрузки и использоваться всеми следующими запусками разметки.
- **FR-022**: Пользователь ДОЛЖЕН иметь возможность проверить подключение и получить
  понятный ответ об успехе или причине неудачи, а также вернуть значения по умолчанию.
- **FR-023**: Время ожидания ответа на одну пачку ДОЛЖНО быть ограничено (по умолчанию
  120 секунд); превышение считается ошибкой пачки.

### Key Entities

- **Метка** (расширение): к названию добавляется необязательное описание — пояснение
  темы для разметки.
- **Набор меток для разметки**: метки, между которыми разметка выбирает в данном
  запуске, плюс неявный вариант «ни одна не подходит».
- **Этап разметки**: выборка слов (фильтры, начальное слово, лимит), набор меток и
  размер пачки, заданные пользователем на один запуск. Существует, пока идёт запуск;
  его итог — метки на словах и сводка.
- **Пачка**: часть этапа, обрабатываемая за один запрос к классификатору; применяется
  к словам целиком или не применяется.
- **Настройки классификатора**: адрес сервиса, ключ доступа, модель; одни на всё
  приложение.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Разметка словаря запускается не более чем за 3 действия со страницы
  «Словарь» (открыть разметку, при желании поправить этап, «Запустить»).
- **SC-002**: На контрольном наборе из 16 слов примера (`spoon` … `cloud`) с метками
  «кухня», «тело», «растение» не менее 14 слов размечены верно, и ни одно из слов
  `bicycle`, `democracy`, `guitar`, `cloud` не получает метку.
- **SC-003**: Ни одна метка не снимается со слова и не дублируется ни при каком числе
  повторных запусков (проверяется сравнением меток до и после).
- **SC-004**: Ни один запуск не меняет статус, расписание и журнал ответов ни одного
  слова (проверяется сравнением до и после).
- **SC-005**: Остановка или сбой на любой пачке теряют не больше одной пачки работы;
  все завершённые пачки остаются на словах.
- **SC-006**: Пользователь видит обновление прогресса не реже чем после каждой пачки и
  в любой момент может остановить разметку.
- **SC-007**: Смена адреса, ключа или модели классификатора не требует правки файлов
  проекта и перезапуска приложения.

## Assumptions

- Классификатор — внешняя по отношению к приложению языковая модель (по умолчанию
  локальная, доступная по `http://localhost:11434`); её установка и запуск — забота
  пользователя, приложение лишь подключается к ней. Без доступной модели разметка не
  работает, остальное приложение — работает.
- Ключ по умолчанию `ollama` — не секрет, а заглушка локального сервиса; хранить его в
  настройках приложения допустимо. Если пользователь укажет настоящий ключ облачного
  сервиса, он хранится так же, без отдельной защиты (приложение локальное и
  однопользовательское).
- Модель отвечает на английском и судит по английскому слову с переводом; названия
  меток могут быть на русском.
- Разметка запускается вручную; автоматического запуска при добавлении слова или
  импорте нет.
- Ход разметки живёт в открытой странице: после перезагрузки незавершённый этап не
  возобновляется сам, пользователь продолжает его с показанного начального слова.
- Слова, которым на прошлом этапе ни одна метка не подошла, при повторном запуске с
  фильтром «Без меток» снова попадут в выборку; отдельная отметка «уже размечалось»
  не ведётся — для этого служит начальное слово этапа.
- Порядок обработки слов в этапе тот же, что в словаре (порядок добавления); он не
  меняется от того, что словам добавляются метки, поэтому начальное слово надёжно
  указывает, где остановился прошлый этап.
- Отмена всего прогона одной кнопкой не входит в эту доработку: добавленные метки
  снимаются вручную или удалением метки целиком.
