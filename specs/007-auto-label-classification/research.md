# Research: Автоматическая разметка слов по меткам

Решения Phase 0. Факты о `typesafe-sdk` взяты из исходников версии 0.7.2 и пробного
запуска против локальной Ollama (`nimble:latest`, 9B) 2026-10-01.

## R1. Вызов модели: `typesafe-sdk`, синхронный клиент на бэкенде

**Decision**: зависимость `typesafe-sdk` (`uv add typesafe-sdk`) в бэкенде. Вызов —
`TypeSafeClient(base_url=…, api_key=…, model=…, timeout=…, retry=RetryPolicy(max_retries=0))`
с явными параметрами, без переменных окружения `TYPESAFE_*`. Один запрос
`system_one(state=…, questions=…)` на пачку. Маршрут разметки — обычный `def`:
FastAPI выполняет его в пуле потоков, и минута ожидания модели не блокирует другие
запросы.

**Rationale**: пользователь прямо назвал SDK. Он умеет ровно то, что нужно: вопрос
`Choice` с критериями на каждое слово, все слова — одним HTTP-запросом
`POST {base_url}/v1/systemone`. Явные параметры важнее переменных окружения:
значения меняются из интерфейса без перезапуска (SC-007), а переданное значение
SDK ставит выше `TYPESAFE_*` (`_core/config.py`), так что случайно выставленная в
оболочке переменная ничего не перебьёт. Зависимости SDK — `httpx2`, `pydantic ≥ 2.12`
— у бэкенда уже есть; новая транзитивная — только `tenacity`. Python ≥ 3.10.

**Проверено вживую**: 4 слова, русские названия категорий, один запрос — 12,6 с с
загрузкой модели, 1 853 входных токена; все 4 ответа верные, уверенность 0,94–0,99.
Ключ Ollama не проверяет.

**Alternatives considered**:
- `AsyncTypeSafeClient` в `async def` маршруте — сессия SQLAlchemy синхронная, и
  чтение/запись пришлось бы выносить в поток вручную. Выигрыша для одного
  пользователя нет.
- Прямой `httpx2` к `/v1/systemone` — пришлось бы повторять схему запроса и ответа
  SDK. Отвергнуто.
- Вызов модели из браузера — фронт не должен ходить во внешние сервисы и решать за
  сервер, какие метки ставить (Принцип I); к тому же CORS у Ollama.

## R2. Настройки подключения: таблица `settings`, значения по умолчанию в `config.py`

**Decision**: адрес, ключ и модель хранятся в существующей key/value-таблице
`settings` (ключи `classifier_*`). Значения по умолчанию — поля `Settings` в
`app/config.py` (`http://localhost:11434`, `ollama`, `nimble`), переопределяемые через
`backend/.env`. Меняются на новой вкладке «Разметка» страницы «Настройки».

**Rationale**: пользователь предложил захардкодить или вынести в интерфейс; интерфейс
закрывает US3 и SC-007, а значение по умолчанию в `config.py` даёт то же, что
хардкод, когда пользователь ничего не настраивал. Прецедент — `new_words_order`: он
так же лежит в `settings` и действует в любом браузере. Миграция не нужна.

**Alternatives considered**:
- Только `backend/.env` — смена модели требует правки файла и перезапуска (SC-007).
- `localStorage` фронта и передача значений в каждом запросе разметки — ключ ездит
  по сети при каждой пачке, а настройки различаются между браузерами.
- Хардкод — пользователь допускал, но смена модели требует правки кода.

## R3. Отбор слов этапа — тот же код, что у `GET /words`

**Decision**: построение фильтра (`search`, `status`, `priority`, `label`) выносится из
`routers/words.py` в функцию `filtered_words(...)` нового модуля
`app/word_filters.py`. Её вызывают и `GET /words`, и разметка; ошибки 422 на
неизвестный статус и метку — там же.

**Rationale**: окно разметки открывается с фильтрами «Словаря», и пользователь ждёт,
что «Без меток» + «Изучается» в разметке значит то же самое, что в списке. Одна функция
не даст определениям разойтись; счётчик «попадёт N слов» берётся из того же `GET
/words` с новым параметром `from_id`.

**Alternatives considered**: передавать в разметку список id, собранный фронтом по
страницам `GET /words` — для 7 000 слов это 35 запросов до старта и список, который
устаревает, пока идёт разметка.

## R4. Этапы без состояния на сервере: курсор по `Word.id`

**Decision**: этап ведёт фронт. Каждая пачка — независимый запрос
`POST /labels/classify` с фильтрами, набором меток, `from_id` и `limit`. Сервер
берёт до `limit` подходящих слов с `id ≥ from_id` по возрастанию `id` и возвращает
`next_from_id` и `remaining`. Фронт повторяет запрос, пока `next_from_id` не `null`,
не достигнут лимит этапа или пользователь не остановил. Ограничение этапа «не больше
N слов» фронт выражает, уменьшая `limit` последней пачки. «Начать с» — слово,
выбранное поиском по словарю, или место остановки из `localStorage`.

**Rationale**: Принцип I запрещает серверные сессии и очереди. Курсор по
первичному ключу стабилен: слово, получившее метку, выпадает из фильтра «Без меток»,
но оно уже позади курсора — смещение `offset` в этом случае пропускало бы слова.
`id` — порядок «Словаря» (`order_by(Word.id)`), так что «продолжить с `kettle`»
пользователь видит там же, где ожидает. Повтор пачки после перезагрузки безопасен:
разметка только добавляет отсутствующие метки (FR-004).

**Alternatives considered**:
- Фоновая задача на сервере с прогрессом по опросу — серверное состояние, очередь и
  восстановление после перезапуска (Принципы I и V).
- `offset` — ломается, когда фильтр «Без меток» теряет размеченные слова.
- Отметка «уже размечалось» на слове — новое поле ради удобства, которое даёт курсор.

## R5. Транзакции пачки: чтение и запись по разные стороны вызова модели

**Decision**: маршрут читает слова и метки, затем `session.commit()` закрывает
транзакцию чтения (`expire_on_commit=False` сохраняет загруженные значения), затем
вызывает модель. После ответа — в новой транзакции заново загружает слова и метки
по id, пропускает удалённые, вставляет в `word_labels` только отсутствующие пары и
коммитит при выходе из `get_session`.

**Rationale**: вызов длится до двух минут. Открытая всё это время транзакция чтения в
SQLite WAL держит старый снимок, и попытка записи после чужой записи (пользователь
поправил слово во второй вкладке) падает с `SQLITE_BUSY_SNAPSHOT`. Повторная
загрузка закрывает гонки из Edge Cases: слово удалили — `skipped`, метку удалили —
не ставится. Пачка применяется целиком или никак (FR-016): ошибка модели
случается до любой записи.

**Alternatives considered**: одна транзакция на весь запрос — риск `database is
locked` и записи меток на удалённое слово (внешний ключ отклонил бы всю пачку).

## R6. Ошибки и таймауты: без повторов, 502 и 504

**Decision**: `RetryPolicy(max_retries=0)`, таймаут пачки
`classifier_timeout_seconds = 120` (как в примере пользователя). Исключения SDK
переводятся в `HTTPException` в одном месте (`classifier.py`):

| Исключение SDK | Код | `detail` |
|---|---|---|
| `TypeSafeAPITimeoutError` | 504 | «Модель не ответила за 120 с — уменьшите пачку» |
| `TypeSafeAPIConnectionError` | 502 | «Сервис разметки недоступен по адресу …» |
| `TypeSafeNotFoundError` | 502 | «Модель «…» не найдена» |
| `TypeSafeAuthenticationError`, `TypeSafePermissionDeniedError` | 502 | «Сервис отклонил ключ доступа» |
| `TypeSafeAPIResponseValidationError` | 502 | «Сервис ответил не по схеме» |
| прочие `TypeSafeAPIError` | 502 | «Сервис разметки ответил ошибкой <status>» |
| `TypeSafeError` (неверная конфигурация) | 502 | текст причины |

Порядок проверки — от частного к общему: `TypeSafeAPITimeoutError` — подкласс
`TypeSafeAPIConnectionError`.

**Rationale**: по умолчанию SDK повторяет таймауты и 5xx дважды — две минуты
ожидания превратились бы в шесть, а пользователь всё это время смотрел бы на
застывший прогресс. Остановка с понятной причиной и кнопкой «Продолжить» честнее
(FR-018). 502/504 — стандартные коды «виноват вышестоящий сервис»; 4xx сказали бы,
что неверен запрос пользователя, а это не так. Конституция перечисляет коды для
ошибок запроса; новые коды добавляются в README в разделе «API».

**Alternatives considered**: повторы SDK по умолчанию; 503 вместо 502 — разницы для
фронта нет, а 502 точнее описывает «ответил ошибкой».

## R7. «Проверить подключение»: один крошечный вопрос модели

**Decision**: `POST /settings/classifier/check` задаёт модели один вопрос `Choice`
с двумя вариантами (`"apple"` — фрукт или инструмент) через тот же клиент с
таймаутом `classifier_check_timeout_seconds = 15`. Успех — `ok: true`; любое
исключение из таблицы R6 — `ok: false` и тот же `detail`.

**Rationale**: `client.models.list()` у SDK ждёт `{"models": [...]}`, а Ollama
отвечает на `/v1/models` в формате OpenAI — SDK падает на разборе. `GET /v1/models`
напрямую проверил бы адрес, но не модель. Один вопрос проверяет всё сразу — адрес,
ключ, модель и поддержку `/v1/systemone` — и стоит меньше секунды на загруженной
модели. Проверка идёт ровно тем путём, что и разметка.

**Alternatives considered**: `models.list()` — несовместим с Ollama; проверка при
сохранении — сохранять настройки для недоступного сейчас сервиса должно быть можно.

## R8. Вопрос модели: слово с переводом, метки как критерии, «ни одна»

**Decision**: в `classifier.py` две чистые функции и тонкий адаптер.

- `build_questions(words, labels)` → `{str(word.id): Choice(instructions, criteria)}`.
  Ключ — id записи: у слова бывает несколько значений, а ключи словаря уникальны.
  `instructions` по-английски: `Which category does the English word "{word}"
  (Russian translation: "{translation}") belong to? Choose "{NONE}" if none fits.`
  `criteria` — `{label.name: label.description or label.name}` плюс
  `{NONE: "None of the above"}`.
- `parse_choices(response, words, labels)` → `{word_id: label_id | None}`.
  Ответ сопоставляется с названием метки точно; `NONE`, отсутствующий ключ или
  ответ вне набора — `None` (SDK не проверяет, что выбор из критериев).
- `NONE = "none of the above"`; если метка названа так же (без учёта регистра), ключ
  получает суффикс до свободного: `none of the above (2)`.
- `state = {"words": [{"word", "translation"}…]}` — как в примере пользователя.

**Rationale**: перевод различает значения (`bark` «кора» и «лаять», Edge Cases,
FR-005). Названия меток русские — проверено вживую, модель понимает их и отвечает
ровно ключом. Описание метки — тот самый «критерий» `Choice`, ради которого оно
заведено (FR-007a). Явный вариант «ни одна» — то, на чём держится FR-003: без него
модель обязана выбрать хоть что-то. `Choice` даёт ровно один ответ — это FR-006.
Чистые функции проверяются табличными тестами без сети.

**Alternatives considered**:
- Порог уверенности (`confidence`) вместо варианта «ни одна» — порог пришлось бы
  подбирать под модель; можно добавить позже поверх, если «ни одна» окажется слабой.
- Ключ вопроса — само слово, как в примере — ломается на нескольких значениях.

## R9. Описание метки: колонка и частичный `PATCH`

**Decision**: `labels.description String(200) NULL` (миграция `add_column`).
`PATCH /labels/{id}` становится частичным (`LabelUpdate`, `exclude_unset`): старый
вызов `{name}` по-прежнему только переименовывает. Описание правится в строке метки
на вкладке «Метки» рядом с переименованием.

**Rationale**: описание — свойство метки, а не настройка разметки, и должно жить
вместе с ней. Частичный `PATCH` не ломает нынешний фронт и не стирает описание при
переименовании.

**Alternatives considered**: описания в `settings` (JSON по id метки) — расходятся с
метками при удалении; отдельный маршрут `PUT /labels/{id}/description` — лишний,
когда `PATCH` и так есть.

## R10. Интерфейс

**Decision**:
- **«Словарь»**: кнопка «Разметить автоматически» открывает панель
  `AutoLabelPanel` над списком. Панель берёт текущие фильтры «Словаря» и
  показывает: набор меток (чипы, все включены), «Не больше N слов», «Начать с»
  (с начала / с места остановки / выбрать слово поиском), размер пачки, число слов
  в этапе и «Запустить». Во время работы — прогресс-полоса «обработано X из Y»,
  счётчики по меткам, «Остановить» (ждёт текущую пачку). После — сводка и
  «Продолжить с «…»».
- После каждой пачки — инвалидация `['words']` и `['labels']`: новые метки видны в
  списке, счётчики на вкладке «Метки» актуальны.
- **«Настройки» → вкладка «Разметка»** (`ClassifierSection`): адрес, ключ, модель,
  «Сохранить», «Проверить подключение», «Сбросить».
- **«Настройки» → «Метки»**: поле описания у метки.
- Запуск недоступен без меток (FR-010) и при пустом этапе — с объяснением.

**Rationale**: фильтры «Словаря» — уже знакомый способ сказать «какие слова»
(FR-013), и окно с ними не заставляет вводить их второй раз. Ожидание остановки
вместо обрыва запроса: оборванный `fetch` не отменяет работу сервера, и фронт не
узнал бы, что пачка применилась.

**Alternatives considered**: отдельная страница разметки — дублировала бы фильтры
словаря; модальное окно — закрывало бы список, в котором видно, как появляются
метки.

## R11. Тесты без сети

**Decision**:
- Маршрут получает классификатор через зависимость `get_classifier`; тесты API
  подменяют её фейком (`app.dependency_overrides`), который отвечает по таблице
  «слово → метка» или бросает заданное исключение SDK.
- Адаптер `TypeSafeClassifier` проверяется с `transport=httpx2.MockTransport(...)`:
  что уходит в `/v1/systemone` (ключи, критерии, «ни одна», модель, Bearer) и как
  ответы и коды 404/401/таймаут превращаются в 502/504.
- `build_questions`/`parse_choices` — табличные тесты (`parametrize`).
- Качество разметки на живой модели (SC-002) — ручной сценарий quickstart, в pytest
  его нет: тесты не ходят в сеть (Принцип III).

**Rationale**: Принцип III — тесты на временной SQLite и без сети. `MockTransport`
встроен в `httpx2`, а `transport=` — штатный параметр клиента SDK.

## R12. Отступления от конституции

- **Внешний сервис и новая зависимость** (Принцип V: «внешние сервисы… не
  добавляются на будущее»). Потребность реальная и названа пользователем; сервис
  необязателен — без него не работает только разметка. Записано в Complexity Tracking.
- **Ключ доступа в базе** (раздел «Конфигурация»: «появление секрета требует
  пересмотра»). Значение по умолчанию `ollama` — заглушка, Ollama ключ не проверяет.
  Ключ лежит в `backend/data/app.db`, который не коммитится, а не в файлах проекта.
  Записано в Complexity Tracking; рекомендована поправка конституции (MINOR):
  «ключ внешнего сервиса хранится в базе, не в репозитории».
- **Коды 502/504** — новые для API; не противоречат правилу «ошибки с `detail`»,
  документируются в README.
