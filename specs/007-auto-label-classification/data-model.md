# Data Model: Автоматическая разметка слов по меткам

Новых таблиц нет. Схема меняется одной колонкой; настройки классификатора ложатся в
существующую таблицу `settings`; ход разметки живёт на фронте.

## labels (изменение)

| Поле | Тип | Правило |
|---|---|---|
| `description` | `String(200)`, NULL | Необязательное пояснение темы для разметки (FR-007a) |

- Длина — до `LABEL_DESCRIPTION_MAX = 200` символов после обрезки крайних пробелов
  (`schemas.py`, рядом с `LABEL_NAME_MAX`). Больше — 422.
- Пустая или пробельная строка сохраняется как `NULL`: «описания нет» имеет одно
  представление.
- Уникальности нет: две метки могут иметь одинаковое описание.
- Существующие метки после миграции получают `NULL` — разметка судит о них по
  названию, как раньше.

**Миграция** `<rev>_label_description.py`: `op.add_column("labels",
sa.Column("description", sa.String(200), nullable=True))`. В SQLite это `ALTER TABLE
ADD COLUMN` без пересоздания таблицы, поэтому `batch_alter_table` не нужен и внешние
ключи `word_labels` не уезжают (Принцип IV). `downgrade` — прямой `op.drop_column`,
как в `db05d4083721_word_priority.py` (SQLite ≥ 3.35 умеет `DROP COLUMN` без
пересоздания таблицы); теряются только описания, разметка остаётся.

## settings (новые ключи, без миграции)

| Ключ | Значение по умолчанию | Правило |
|---|---|---|
| `classifier_base_url` | `http://localhost:11434` | `http://` или `https://`, 1…512 символов |
| `classifier_api_key` | `ollama` | 1…512 символов, без крайних пробелов |
| `classifier_model` | `nimble` | 1…128 символов, без крайних пробелов |

- Значения по умолчанию — поля `Settings` в `app/config.py` (`classifier_base_url`,
  `classifier_api_key`, `classifier_model`), переопределяемые через `backend/.env`.
- Строки нет — действует значение по умолчанию. «Сбросить» удаляет строки, а не
  записывает значения по умолчанию: тогда смена значения в `config.py` доходит до
  пользователя, который ничего не менял.
- Три значения сохраняются одной транзакцией: не бывает адреса от одного сервиса и
  модели от другого.

## Параметры в `app/config.py` (новые)

| Параметр | Значение | Зачем |
|---|---|---|
| `classifier_timeout_seconds` | `120.0` | Предел ожидания одной пачки (FR-023), как в примере пользователя |
| `classifier_check_timeout_seconds` | `15.0` | Предел ожидания «Проверить подключение»: проверка не должна висеть две минуты |
| `classifier_batch_max` | `100` | Верхняя граница размера пачки (FR-012): больше — один запрос дольше таймаута на локальной модели |

## Отношения, которые разметка создаёт

Разметка только **добавляет** строки в `word_labels` (`word_id`, `label_id`):

- не больше одной строки на слово за пачку (FR-006);
- строка, которая уже есть, не добавляется повторно и не считается добавленной
  (FR-004) — составной первичный ключ и так её не пустит, но сервис проверяет заранее,
  чтобы сводка была честной;
- строки не удаляются никогда;
- `progress`, `review_log`, `words` не меняются (FR-008).

## Временные сущности (не хранятся на сервере)

### Этап разметки (фронт, память страницы)

| Поле | Откуда | Правило |
|---|---|---|
| `filters` | Фильтры «Словаря» на момент открытия | `search`, `status`, `priority`, `label` — те же, что у `GET /words` |
| `label_ids` | Набор меток | ≥ 1; по умолчанию все метки (FR-014) |
| `from_id` | «Начать с» | `null` — с начала; иначе id записи, с которой начать |
| `limit` | «Не больше N слов» | `null` — вся выборка; иначе ≥ 1 |
| `batch_size` | «Размер пачки» | 1…`classifier_batch_max`, по умолчанию 20 |

### Курсор

`next_from_id` из ответа пачки — id, с которого начнётся следующая. Слова
обходятся по `Word.id`, как в «Словаре», поэтому курсор не сдвигается, когда слова
получают метки и выпадают из фильтра «Без меток» (R4).

### Состояние запуска (фронт)

```text
idle ──Запустить──▶ running ──пачка ок, есть ещё, не достигнут limit──▶ running
                       │
                       ├──пачка ок, слов больше нет / limit──▶ done
                       ├──Остановить (ждёт текущую пачку)──▶ stopping ──▶ stopped
                       └──ошибка пачки──▶ failed
done | stopped | failed ──Закрыть / Новый этап──▶ idle
```

`stopped` и `failed` показывают слово, с которого продолжить (`next_from_id` и его
`word`), и кнопку «Продолжить», которая запускает этап с этим `from_id`.

### Запомненное между запусками (`localStorage`, по браузеру)

| Ключ | Значение |
|---|---|
| `autoLabel.batchSize` | последний размер пачки (FR-019) |
| `autoLabel.limit` | последнее ограничение числа слов |
| `autoLabel.resume` | `{ from_id, word }` — где остановился прошлый этап |

Это удобство одного браузера (как выбранный голос), а не данные: при пустом
хранилище действуют значения по умолчанию и этап начинается с начала.

### Сводка (фронт)

Накапливается из ответов пачек: `processed`, `added` по каждой метке,
`unchanged` (метка не подошла или уже стояла), `skipped` (слово удалили во время
пачки).
