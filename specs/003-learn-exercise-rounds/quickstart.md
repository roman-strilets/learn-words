# Quickstart — проверка доработки «Изучение раундами»

Как убедиться, что фича работает: сначала автоматические ворота, потом сценарии,
которые проходятся руками. Детали контракта — в [contracts/study-api.md](./contracts/study-api.md),
правила состояний — в [data-model.md](./data-model.md).

## Предварительно

```bash
yarn setup          # один раз: зависимости бэка и фронта
yarn dev            # бэкенд + фронтенд, порты из корневого .env
```

В словаре нужно хотя бы 10 новых слов (`yarn` импорт `dictionary.csv` или страница
«Добавить слово»), иначе занятие соберётся короче пяти слов и часть сценариев не
проверить.

## Ворота (обязательны перед коммитом)

```bash
yarn test:api                                        # pytest, backend/tests
yarn typecheck                                       # tsc -b, синхронность types.ts и schemas.py
yarn build                                           # сборка фронта
uv run --directory backend ruff check app tests      # стиль Python
```

Падение любой проверки блокирует коммит (конституция, раздел «Рабочий процесс»).

## Ручные сценарии

### 1. Знакомство идёт впереди упражнений (FR-002, FR-003, SC-002)

Открыть «Учить слова». Пройти пять карточек знакомства, нажимая «Изучить».
Ожидаемо: до пятой карточки включительно упражнений нет; после неё начинается первый
раунд и появляется шапка «Раунд 1 из 4 · Выбор перевода: рус → англ».

### 2. Раунды идут группами в заданном порядке (FR-004, FR-006, SC-001, SC-003)

Отвечать только верно. Ожидаемо: 5 карточек `choice_ru_en`, затем 5 `choice_en_ru`,
затем 5 `letters`, затем 5 `dictation` — итого 25 карточек за занятие вместе со
знакомством. Тип меняется только на границе раунда.

### 3. Ошибка возвращает слово в тот же раунд (FR-008, FR-008a, FR-009, SC-004)

В первом раунде ответить неверно на одном слове. Ожидаемо: слово появляется снова
в этом же раунде, с тем же типом упражнения, но с другими вариантами ответа; появляется
оно не сразу следующей карточкой, а после остальных; счётчик оставшихся карточек
вырос на единицу.

### 4. Следующий раунд ждёт весь текущий (FR-010, SC-005)

Ошибаться на одном слове несколько раз подряд. Ожидаемо: второй раунд не начинается,
пока это слово не отвечено верно; число попыток не ограничено.

### 5. «Уже знаю» меняет состав раундов (FR-019)

На знакомстве отметить одно слово «Уже знаю». Ожидаемо: взамен предлагается новое
слово, знакомство продолжается; в первом раунде столько карточек, сколько слов взято
в изучение, и отмеченного слова среди них нет.

### 6. Итог занятия одинаков для слов с ошибками и без (FR-015, FR-015b, SC-006, SC-007)

Пройти занятие целиком, ошибившись ровно на одном слове. После завершения открыть
«Словарь» и сравнить это слово с любым другим из занятия. Ожидаемо: у обоих статус
«Повторение», срок — завтра, `ease` одинаковый, счётчик забываний нулевой.

Проверка тем же запросом:

```bash
sqlite3 backend/data/app.db \
  "select word_id, status, interval_days, ease, lapses from progress order by updated_at desc limit 5;"
```

### 7. Прерванное занятие не выпускает слова (FR-016, SC-010)

Начать занятие, пройти знакомство и два раунда, уйти со страницы. Ожидаемо: слова
остались в статусе «Изучение» со сроком «сегодня»; их попытки видны на странице
«Статистика»; ни одно не перешло в «Повторение». Такие слова попадут в занятие
«Повторить слова».

### 8. Режим «Повторение» не изменился (FR-021)

Пройти занятие «Повторить слова» целиком. Ожидаемо: четыре раунда как раньше, шапка
и счётчик на месте, слово с ошибкой откатилось в «Изучение» со сроком «сегодня» и
увеличенным счётчиком забываний — то есть повторение по-прежнему наказывает за ошибку,
в отличие от изучения.

### 9. Слово выбыло по ходу занятия (FR-020)

Во время занятия в другой вкладке перевести одно из слов занятия в статус «Знаю».
Вернуться и продолжить. Ожидаемо: карточка этого слова исчезает из очереди, занятие
идёт дальше на остальных словах и нормально завершается.
