# Tasks: Изучение раундами по типам упражнений

**Input**: Design documents from `/specs/003-learn-exercise-rounds/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md),
[data-model.md](./data-model.md), [contracts/study-api.md](./contracts/study-api.md),
[quickstart.md](./quickstart.md)

**Tests**: обязательны, и не по выбору. Конституция, принцип III: любое изменение SRS,
генерации упражнений, проверки ответов или контракта API ДОЛЖНО сопровождаться тестом
в `backend/tests/` в том же коммите. Доработка меняет всё четыре — тестовые задачи
идут наравне с кодом, а не «если попросят».

**Organization**: задачи сгруппированы по пользовательским историям. Оговорка ниже
(«Реальность поставки») объясняет, почему истории здесь проверяются независимо,
но поставляются одним коммитом.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно делать параллельно (другой файл, нет зависимостей)
- **[Story]**: к какой истории относится задача (US1, US2, US3, US4)
- В описании — точный путь к файлу

## Path Conventions

Веб-приложение, два дерева из корня репозитория: `backend/app/`, `backend/tests/`,
`frontend/src/`. Новых каталогов не заводится.

## Реальность поставки

Фазы задают **порядок работы**, а не последовательность коммитов. Фронтенд связан со
схемой через `yarn typecheck` (принцип III): как только из `SelectResponse` уходит
`next_exercise`, `StudySession.tsx` перестаёт собираться. Поэтому Phase 2 и Phase 3
зелёными воротами по отдельности не заканчиваются — доработка ложится **одним
коммитом** (принцип «один коммит — одно законченное изменение»). Чекпойнты фаз
означают «этот кусок дописан и его тесты проходят», а не «можно коммитить и катить».

Истории US2, US3, US4 после Phase 3 почти не требуют нового кода: их поведение даёт
общий `RoundsRunner`. Их задачи — это проверки, что вынесенный раннер действительно
даёт нужное поведение и в режиме изучения, и переписанные тесты старой пошаговой
модели. Это честнее, чем изобретать им отдельные реализации.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: без зависимостей
- **Foundational (Phase 2)**: после Setup — блокирует все истории
- **US1 (Phase 3)**: после Phase 2. Блокирует US2, US3, US4: без работающего раннера изучения проверять их нечем
- **US2 (Phase 4)**, **US3 (Phase 5)**, **US4 (Phase 6)**: после Phase 3, между собой независимы
- **Polish (Phase 7)**: после всех историй

### Внутри Phase 2

```text
T002 → T003 → T004        (srs.py, затем его тесты)
T003 ─┐
T005 ─┴→ T006 → T007 → T008     (схемы → сервис → финиш → роутер)
T005 → T009 → T010 → T011       (схемы → типы → клиент → раннер)
T008 + T011 → T012              (существующие тесты повторения)
```

### Отступление от шаблона: историй, независимых друг от друга, здесь нет

Шаблон предполагает, что истории можно вести параллельно разными людьми. В этой
доработке US2, US3 и US4 — грани одного раннера, собранного в US1; отдельно от неё они
не существуют. Плана это не ломает: истории всё равно **проверяются** независимо
(каждая имеет свой сценарий в quickstart), но **делаются** последовательно.

### Parallel Opportunities

Настоящей параллельности мало, и выдумывать её не стоит: почти все серверные тесты
живут в одном `backend/tests/test_api.py`, а изменения `srs.py` → `schemas.py` →
`study_service.py` → `routers/study.py` выстроены в цепочку. Реально независимы:

- **T004** (`backend/tests/test_srs.py`) — параллельно любой работе по `test_api.py`
- **T030** (README) и **T031** (чистка фронта) — разные файлы, параллельны друг другу
- Ручные сценарии (**T022**, **T025**, **T029**, **T033**) — параллельны написанию тестов

Задачи T015–T021, T023, T026, T027 трогают один файл `backend/tests/test_api.py` и
метки `[P]` намеренно не получили: параллельный запуск дал бы конфликты в одном файле.

## Implementation Strategy

### MVP

Phase 1 → Phase 2 → Phase 3. На этом занятие «Изучение» уже целиком работает по
раундам: знакомство, четыре типа, ошибка возвращает слово в раунд, итог выпускает
слово в повторения. Остановиться здесь и пройти сценарии 1 и 2 из quickstart.

### Инкременты
