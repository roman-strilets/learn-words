# Phase 1 — Data Model: Изучение раундами по типам упражнений

Схема базы не меняется: таблицы `words`, `progress`, `review_log` остаются прежними,
миграции нет. Меняются жизненный цикл слова в занятии-изучении и набор сущностей,
которыми обмениваются фронт и бэкенд.

---

## Сущности хранилища (без изменений)

### `progress` — прогресс слова

| Поле | Что значит после доработки |
|---|---|
| `status` | `learning` / `review` / `known` / `suspended` — без изменений |
| `step` | **Смысл сужается**: только счётчик успешных занятий у слова, откатившегося в изучение после забывания. Тип упражнения из него больше не выводится (R5) |
| `repetitions`, `ease`, `interval_days`, `lapses`, `due_at` | Без изменений |
| `started_at`, `updated_at` | Без изменений; `updated_at` по-прежнему даёт идемпотентность финиша |

### `review_log` — журнал попыток

Колонки без изменений, включая `session_id` (nullable, заведена фичей 001).
Что меняется в наполнении:

- В режиме `learn` каждая попытка теперь пишется с `session_id` — раньше он был только
  у повторения. Записи прежних занятий-изучений остаются с `NULL` и продолжают
  считаться в статистике.
- `status_before` и `status_after` в попытках занятия-изучения **совпадают**: ответ
  внутри занятия состояние не двигает (FR-015a). Раньше они расходились на каждом шаге.
- Попытка `intro` пишется как и сейчас — при нажатии «Изучить» или «Уже знаю», без
  `session_id` (знакомство не входит в раунды и на финиш не влияет).

---

## Сущности контракта

### `ExerciseRound` (переименование `ReviewRound`)

Раунд: один тип упражнения на все слова занятия. Имя меняется, потому что раунды
перестают быть принадлежностью повторения.

| Поле | Тип | Смысл |
|---|---|---|
| `exercise` | `ExerciseType` | Тип упражнения раунда |
| `exercises` | `Exercise[]` | По одной карточке на каждое слово занятия |

**Правила**: длина `exercises` равна числу слов занятия; `exercise` не бывает `intro`
(FR-007); порядок раундов в списке — `EXERCISE_ROUNDS` (FR-006).

### `SessionOut`

| Поле | Что меняется |
|---|---|
| `session_id` | **Теперь выдаётся и в режиме `learn`** — когда есть хоть одно новое слово. Это по-прежнему не серверное состояние, а ключ корреляции в журнале |
| `new_words` | Без изменений: слова на знакомство в режиме `learn` |
| `rounds` | Без изменений: заполнено только в режиме `review`. В `learn` остаётся пустым — план приходит отдельным запросом (R1) |
| `mode`, `counts` | Без изменений |

### `RoundsRequest` (новая)

| Поле | Тип | Смысл |
|---|---|---|
| `word_ids` | `int[]` | Слова, взятые в изучение по итогам знакомства |

**Правила**: пустой список — не ошибка, ответом идёт пустой список раундов (все слова
отмечены «Уже знаю», FR-019 сценарий 3). Слово без прогресса или удалённое из словаря
молча пропускается: его могли вывести из оборота между знакомством и запросом (FR-020).

### `SelectResponse`

| Поле | Что меняется |
|---|---|
| `next_exercise` | **Удаляется**: упражнения больше не приходят по одному вслед за знакомством |
| `progress`, `replacement` | Без изменений |

### `AnswerRequest`

| Поле | Что меняется |
|---|---|
| `session_id` | **Становится обязательным в обоих режимах** (был обязателен только при `mode: "review"`). Без ключа занятия попытку некуда записать, и финиш не соберёт итог |
| `mode`, `word_id`, `exercise`, `answer`, `used_hint`, `attempt`, `duration_ms` | Без изменений |

### `SessionFinishRequest` (переименование `ReviewFinishRequest`)

| Поле | Тип | Смысл |
|---|---|---|
| `session_id` | `str` | Ключ занятия |
| `mode` | `SessionMode` | Как выводить итог: `review` — по худшей попытке, `learn` — выпуск независимо от ошибок (R3, R4) |

### `SessionFinishResult` (переименование `ReviewFinishResult`)

Поля прежние (`word_id`, `mistakes`, `quality`, `progress`). В режиме `learn`
`mistakes` остаётся информационным — на расписание он не влияет (FR-015b), а `quality`
равно оценке, с которой слово выпущено.

## Переходы состояния слова

### Занятие-изучение

```text
нет прогресса (новое слово)
        │  «Изучить» на знакомстве  →  прогресс: learning, step 0, due = сейчас
        │  «Уже знаю»               →  прогресс: known (слово выходит из оборота)
        ▼
learning, step 0
        │  четыре раунда: ответы пишутся в журнал, состояние НЕ меняется (FR-015a)
        │
        ├── занятие прервано  →  остаётся learning, step 0, due «сегодня»;
        │                        попадёт в занятие-повторение (FR-016)
        ▼
все четыре раунда пройдены → POST /study/finish {mode: "learn"}
        │
        ▼
review, step 4, repetitions 1, interval 1 день, ease без изменений,
lapses без изменений — одинаково для слов с ошибками и без (FR-015b)
```

### Занятие-повторение (не меняется, FR-021)

Итог по худшей попытке за занятие: ошибка возвращает слово в `learning` со
`step = RELEARN_STEP`, поднимает `lapses`, снижает `ease`, ставит срок «сегодня».

## Инварианты

1. **Внутри занятия расписание неподвижно.** Для любой попытки занятия
   `status_before == status_after`, а `progress.updated_at` не растёт до финиша
   (FR-015a). Верно теперь для обоих режимов.
2. **Одно обновление расписания на слово за занятие** (FR-015). Повторный финиш с тем
   же `session_id` ничего не пересчитывает: `progress.updated_at` уже позже последней
   попытки занятия.
3. **Слово считается прошедшим занятие**, только если в журнале под этим `session_id`
   есть верный ответ по каждому из четырёх типов `EXERCISE_ROUNDS`. Иначе финиш его не
   трогает (FR-016).
4. **Слово, выбывшее из оборота**, финиш пропускает: статус вне
   (`learning`, `review`) — не наш случай (FR-020).
5. **`intro` не входит в раунды** и не участвует в проверке полноты занятия (FR-007).
