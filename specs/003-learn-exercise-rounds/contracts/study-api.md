# Contract: HTTP-эндпоинты занятия

Все маршруты под `/api`, фронт ходит по относительным путям через прокси Vite.
Ошибки — с человекочитаемым `detail`. Ниже только то, что доработка меняет или
добавляет; остальные эндпоинты занятия остаются как есть.

---

## `GET /api/study/session?mode=learn`

**Меняется**: в ответе появляется `session_id`.

```jsonc
{
  "mode": "learn",
  // Ключ занятия. Выдаётся, когда есть хоть одно новое слово; иначе null.
  // Не серверное состояние — колонка журнала, по которой попытки занятия
  // находят друг друга на финише.
  "session_id": "0f4c…",
  "new_words": [ { "id": 12, "word": "scrutiny", "translation": "…", "…": null } ],
  "rounds": [],          // в режиме learn всегда пусто: план приходит из /study/rounds
  "counts": { "new": 5, "learning": 0, "review_due": 0, "in_study": 41 }
}
```

**Не меняется**: правила отбора слов (новые слова в порядке словаря, дневной лимит),
пустой ответ при отсутствии новых слов, режим `review`.

---

## `POST /api/study/rounds` (новый)

План раундов для готового списка слов. Зовётся один раз, когда знакомство пройдено.

**Запрос**

```jsonc
{ "word_ids": [12, 34, 56, 78, 90] }
```

**Ответ 200** — список раундов в порядке `EXERCISE_ROUNDS`:

```jsonc
[
  { "exercise": "choice_ru_en", "exercises": [ /* по карточке на каждое слово */ ] },
  { "exercise": "choice_en_ru", "exercises": [ … ] },
  { "exercise": "letters",      "exercises": [ … ] },
  { "exercise": "dictation",    "exercises": [ … ] }
]
```

**Правила**

- Пустой `word_ids` → пустой список раундов (не ошибка): все слова могли быть отмечены
  «Уже знаю».
- Слово без прогресса, удалённое или выведенное из оборота — молча пропускается: его
  могли изменить между знакомством и запросом. Отсутствие слова не должно ломать
  занятие (FR-020).
- Если после отсева не осталось ни одного слова, ответ — пустой список.
- Состояния не создаёт: повторный вызов вернёт другие дистракторы и другой порядок
  букв, но будет так же валиден.
- Карточка `intro` не выдаётся ни в одном раунде (FR-007).

## `POST /api/study/answer`

**Меняется**: `session_id` обязателен в обоих режимах; ответ в режиме `learn` больше
не двигает расписание.

```jsonc
{
  "word_id": 12,
  "exercise": "choice_ru_en",
  "answer": "scrutiny",
  "used_hint": false,
  "attempt": 1,            // сквозной номер показа внутри раунда, сброс на границе
  "duration_ms": 4200,
  "mode": "learn",         // learn | review
  "session_id": "0f4c…"    // обязателен: без него попытку некуда записать (422)
}
```

**Ответ 200** — прежняя форма. Что меняется в поведении:

- `progress` в ответе отражает состояние **до** занятия и не двигается — одинаково для
  `learn` и `review` (FR-015a).
- `repeat_in_session` теперь в обоих режимах значит одно: «карточка вернётся в текущий
  раунд». Истинно ровно тогда, когда ответ неверен.
- `next_exercise` при ошибке — карточка того же типа, собранная заново: другие варианты
  ответа, другой порядок букв (FR-008a). При верном ответе — `null`.

**Ошибки**: 404 — слова нет; 409 — слово не взято в изучение; 422 — нет `session_id`.
404 и 409 клиент трактует как «слово выбыло из занятия» и исключает его из оставшихся
раундов.

## `POST /api/study/finish` (переименование `POST /api/study/review/finish`)

Конец занятия: расписание слов пересчитывается один раз, по журналу занятия.

**Запрос**

```jsonc
{
  "session_id": "0f4c…",
  "mode": "learn"          // learn | review — как выводить итог
}
```

**Ответ 200**

```jsonc
[ { "word_id": 12, "mistakes": 1, "quality": 5, "progress": { "…": "…" } } ]
```

**Правила**

- В список попадают только слова, у которых в журнале этого занятия есть верный ответ
  по каждому из четырёх типов. Незавершённые слова не трогаются вовсе (FR-016).
- `mode: "review"` — итог по худшей попытке за занятие: ошибка откатывает слово в
  изучение, поднимает `lapses`, снижает `ease` (поведение не меняется, FR-021).
- `mode: "learn"` — слово выпускается в повторения независимо от ошибок: статус
  `review`, интервал 1 день, `ease` и `lapses` без изменений (FR-015b). `mistakes`
  в ответе остаётся информационным.
- Слово, выведенное из оборота или удалённое во время занятия, пропускается.
- Идемпотентно: повторный вызов с тем же `session_id` второй раз ничего не
  пересчитывает.
- Неизвестный `session_id` — не ошибка, а пустой список.

## `POST /api/study/select`

**Меняется**: из ответа удаляется `next_exercise`.

```jsonc
{
  "progress": { "status": "learning", "step": 0, "…": "…" },
  "replacement": { "id": 77, "word": "…", "…": "…" }   // только для action: "know"
}
```

Что меняется в поведении: «Изучить» просто заводит прогресс слова
(статус `learning`, шаг 0, срок «сейчас») и пишет попытку `intro` в журнал — вызова
`apply_answer` больше нет, шаг не поднимается. Правила замены за «Уже знаю» и
`exclude_ids` не меняются.

## Сводка изменений контракта

| Эндпоинт | Изменение |
|---|---|
| `GET /study/session?mode=learn` | + `session_id` в ответе |
| `POST /study/rounds` | новый |
| `POST /study/answer` | `session_id` обязателен в обоих режимах; `learn` не двигает расписание |
| `POST /study/review/finish` | → `POST /study/finish`, + `mode` в запросе |
| `POST /study/select` | − `next_exercise` в ответе |

Переименования схем: `ReviewRound` → `ExerciseRound`,
`ReviewFinishRequest` → `SessionFinishRequest`,
`ReviewFinishResult` → `SessionFinishResult`.
`frontend/src/api/types.ts` правится в том же коммите (Принцип III).
