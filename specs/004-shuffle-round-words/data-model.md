# Data Model: Случайный порядок слов в каждом раунде

Схема базы не меняется, миграций нет. Меняется только то, что уходит клиенту
и живёт в памяти занятия.

## ExerciseRound (ответ API, без изменений в схеме)

| Поле | Тип | Что меняется |
|---|---|---|
| `exercise` | `ExerciseType` | — |
| `exercises` | `list[Exercise]` | Порядок элементов теперь случайный и свой для каждого раунда |

**Инварианты** плана из `n` слов, раунды `R1…R4`:

- В каждом `Rk` каждое слово встречается ровно один раз (FR-006).
- `n ≥ 2`: `order(Rk) ≠ order(Rk-1)` для `k = 2…4` (FR-003).
- `n ≥ 3`: `Rk[0].word_id ≠ Rk-1[-1].word_id` (FR-004, по плану без ошибок).
- Порядок `R1` — равномерная случайная перестановка (SC-003).

`order(R)` — список `word_id` в порядке элементов.

## Состояние раннера раундов (фронт, в памяти)

| Поле | Назначение |
|---|---|
| `roundOrder: number[]` | Новое. Порядок первых показов текущего раунда, как он показан (после поправки и отсева выбывших) |
| `lastWordId: number \| null` | Новое. `word_id` последней отвеченной карточки, включая повтор после ошибки |
| `queue`, `dropped`, `shows`, `roundIndex` | Как сейчас |

**Переход на границе раунда** (очередь пуста, обратной связи нет):

```text
next      = rounds[k+1].exercises без выбывших
previous  = roundOrder без выбывших
arranged  = arrangeRound(next, previous, lastWordId)
queue     = arranged
roundOrder = arranged.map(word_id)
```

Повторы после ошибки дописываются в конец `queue` и в `roundOrder` не попадают.
