# Contract: порядок карточек в плане раундов

Схемы запросов и ответов не меняются. Меняется только гарантия о порядке элементов
`exercises` в раундах. Эта гарантия действует в обоих местах, где сервер отдаёт план:

- `GET /api/study/session?mode=review` → поле `rounds`;
- `POST /api/study/rounds` → тело ответа.

## Гарантии

Для плана из `n` слов и раундов в порядке `EXERCISE_ROUNDS`:

1. В каждом раунде по одной карточке на каждое слово. Слова не теряются и не дублируются.
2. Порядок карточек в первом раунде случайный. Он не привязан ни к порядку словаря,
   ни к порядку `word_ids` в запросе, ни к порядку отбора «самые просроченные первыми».
3. `n ≥ 2`: порядок `word_id` в каждом раунде, начиная со второго, отличается
   от порядка в предыдущем раунде.
4. `n ≥ 3`: первая карточка раунда, начиная со второго, не того же слова, что последняя
   карточка предыдущего раунда.
5. Два вызова с одинаковыми словами могут вернуть разный порядок. Клиент не должен
   рассчитывать на стабильность порядка.

## Обязанности клиента

Гарантии 3 и 4 относятся к плану. Если занятие отклонилось от плана (повтор после
ошибки в конце раунда, выбывшее слово), клиент на границе раунда переупорядочивает
следующий раунд по тем же правилам, опираясь на то, что показал на самом деле
(см. [research.md](../research.md#r3-стык-раундов-после-повтора)). Состав раунда
клиент не меняет.

## Не меняется

- Порядок раундов (`choice_ru_en → choice_en_ru → letters → dictation`).
- `new_words` в `GET /api/study/session?mode=learn`: порядок знакомства прежний.
- `POST /api/study/answer`, `POST /api/study/finish`.
