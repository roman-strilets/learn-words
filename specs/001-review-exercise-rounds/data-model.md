# Phase 1 — Data Model: Повторение раундами по типам упражнений

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-08-29

## Изменения в схеме БД

### `review_log` — одна новая колонка

| Поле | Тип | Ограничения | Зачем |
|---|---|---|---|
| `session_id` | `String(36)` | nullable, индекс `ix_review_log_session_id` | Ключ занятия-повторения. По нему `finish` собирает все попытки занятия и выводит итог. `NULL` — ответ вне занятия-повторения (режим «Изучение» и все строки, накопленные до доработки) |

Миграция Alembic: `op.add_column` + `op.create_index`, без `batch_alter_table` —
таблица не пересоздаётся, внешний ключ `review_log.word_id → words.id` не двигается.
`downgrade` — `op.drop_index` + `op.drop_column` напрямую.

Других изменений схемы нет: `progress`, `words`, `settings` не трогаются.

## Сущности уровня приложения

### Занятие-повторение (не хранится, живёт в ответе API и на клиенте)

| Поле | Тип | Описание |
|---|---|---|
| `session_id` | UUID-строка | Выдаётся сервером при сборке занятия |
| `rounds` | список раундов | Ровно `len(REVIEW_ROUNDS)` = 4 элемента, в фиксированном порядке |
| `counts` | `SessionCounts` | Существующие счётчики занятия |

Правила:
- Слова отбираются прежним запросом `_due_words(...)`: активные статусы,
  `due_at <= now`, сортировка по `due_at`, лимит `settings.review_words_per_session` (FR-001).
- Если подошедших слов нет, `rounds` пуст, `session_id` не выдаётся — экран
  «На сегодня всё» остаётся прежним.

### Раунд

| Поле | Тип | Описание |
|---|---|---|
| `exercise` | `ExerciseType` | Тип упражнения раунда |
| `exercises` | список `Exercise` | По одному упражнению на каждое слово занятия, в порядке отбора слов |

Порядок раундов (FR-004), константа `REVIEW_ROUNDS` в `srs.py`:

1. `choice_ru_en` — показан перевод, выбрать английское слово
2. `choice_en_ru` — показано английское слово, выбрать перевод
3. `letters` — собрать английское слово из букв по переводу
4. `dictation` — записать услышанное английское слово

`intro` в повторении не участвует (FR-005).

### Попытка (строка `review_log`)

Существующие поля сохраняют смысл; уточняются два:

| Поле | Значение в занятии-повторении |
|---|---|
| `session_id` | Идентификатор занятия |
| `attempt` | Номер показа слова в текущем раунде: 1 на первом показе, +1 на каждый повтор после ошибки; со сменой раунда снова 1 (FR-012a). Карточка со сборкой из букв дополнительно поднимает значение до 2 при промахах — смысл тот же, «не с первой попытки» |
| `status_before` / `status_after` | В занятии-повторении совпадают: расписание внутри занятия не меняется (FR-013a) |
| `ease_after` / `interval_after` | Значения на момент ответа, то есть до финального пересчёта |

### Итог слова за занятие (вычисляется на `finish`, не хранится)

| Поле | Тип | Описание |
|---|---|---|
| `word_id` | int | Слово занятия |
| `completed` | bool | По каждому из четырёх типов есть строка с `correct = true` в этом `session_id` |
| `mistakes` | int | Количество строк с `correct = false` в этом `session_id` |
| `quality` | 0–5 | `min(derive_quality(...))` по всем попыткам слова в занятии |

Правила:
- Расписание пересчитывается только для слов с `completed = true` (FR-013, FR-017a).
- `mistakes > 0` даёт `quality = 2`, то есть штатный откат: слово возвращается в
  `learning` на шаг `RELEARN_STEP`, `lapses + 1`, `ease` снижается, `due_at = now`
  (FR-014). Число ошибок сверх первой на расписание не влияет.
- `mistakes = 0` даёт `quality` 5, 4 или 3 в зависимости от подсказок и повторных
  попыток внутри карточек — прежняя таблица оценок из README не меняется.
- Слова с `completed = false` не трогаются вообще: ни `progress`, ни `updated_at`.

## Переходы состояния слова

```
                     занятие-повторение
                 ┌───────────────────────────┐
  review  ──────►│  4 раунда, ответы в лог,  │
  (due_at<=now)  │  прогресс НЕ меняется     │
                 └───────────┬───────────────┘
                             │ finish
              ┌──────────────┴───────────────┐
    ошибок не было                      была ошибка
              │                               │
              ▼                               ▼
   review, repetitions+1,            learning, step=RELEARN_STEP,
   interval × ease, due_at           repetitions=0, lapses+1,
   в будущем                         ease−0.20, due_at = now

  занятие прервано до конца раундов → состояние не меняется вовсе
```

Переходы выполняются существующей чистой функцией `srs.apply_answer(...)` — новых
правил расписания не появляется, меняется только момент вызова и источник `quality`.

## Новое в чистом ядре (`srs.py`)

| Имя | Сигнатура | Описание |
|---|---|---|
| `REVIEW_ROUNDS` | `tuple[ExerciseType, ...]` | Порядок раундов повторения |
| `session_quality` | `(outcomes: Iterable[AttemptOutcome]) -> int` | Итоговая оценка слова за занятие: минимум из `derive_quality` по всем попыткам. Пустой ввод — ошибка вызывающего, функция его не получает |

Удаляются: `REVIEW_EXERCISES`, `_REVIEW_WEIGHTS`, `_REVIEW_WEIGHTS_LATE`,
`pick_review_exercise`. Ветка `status == REVIEW` в `exercise_for` больше не нужна:
после доработки функция вызывается только для слов в `learning`.
