# Quickstart — проверка режима «Повторение» раундами

**Feature**: [spec.md](./spec.md) | **Contract**: [contracts/study-api.md](./contracts/study-api.md)

## Предпосылки

- Node ≥ 22.12 (`.nvmrc`), Python ≥ 3.12, `uv`, `yarn`
- Установка и данные: `yarn setup` (синхронизирует зависимости, накатывает миграции,
  импортирует `dictionary.csv`)
- После доработки схемы: `yarn db:upgrade` — колонка `review_log.session_id`

## Ворота качества (обязательны перед коммитом)

```bash
yarn test:api
yarn typecheck
yarn build
uv run --directory backend ruff check app tests
```

## Автоматическая проверка

Тесты, которые должны появиться или измениться (подробности — в `tasks.md`):

| Файл | Что закрывает |
|---|---|
| `backend/tests/test_srs.py` | Порядок `REVIEW_ROUNDS` (FR-004); `session_quality` даёт 2 при любой ошибке и 5/4/3 без ошибок (FR-013, FR-014) |
| `backend/tests/test_exercises.py` | Повторная карточка того же типа собрана заново: другой порядок букв / другие варианты (FR-006a) |
| `backend/tests/test_api.py` | План занятия: 4 раунда в фиксированном порядке, по одному упражнению на слово (FR-002…FR-005); ответ с `mode=review` не меняет `progress` (FR-013a); неверный ответ возвращает `next_exercise` того же типа (FR-006); `finish` пересчитывает расписание один раз (SC-005), откатывает слово с ошибкой (FR-014), пропускает незавершённые слова (FR-017a) и не пересчитывает дважды |

Запуск точечно:

```bash
uv run --directory backend pytest tests/test_api.py -k review -q
```

## Ручная проверка

```bash
yarn dev            # api на UVICORN_PORT, веб на WEB_PORT
```

Подготовка данных, если словами к повторению стенд не располагает: перевести
несколько слов в статус «На повторении» на странице «Словарь» — у слов без расписания
срок выставится сразу.

### Сценарий 1 — безошибочное занятие (User Story 1, User Story 3)

1. Открыть «Повторение».
2. Пройти занятие, отвечая только верно.
3. Ожидается: 4 раунда по числу слов, типы идут в порядке
   «выбор рус→англ» → «выбор англ→рус» → «буквы» → «аудирование»;
   всего карточек = слов × 4 (SC-001, SC-002); индикатор показывает «Раунд N из 4» (FR-016).
4. После финального экрана открыть «Словарь»: у каждого слова срок повторения
   сдвинулся в будущее, статус остался «На повторении» (SC-005).

### Сценарий 2 — ошибка внутри раунда (User Story 2)

1. Начать занятие и намеренно ошибиться на одном слове в первом раунде.
2. Ожидается: слово возвращается в этот же раунд после остальных карточек (FR-007),
   тип упражнения тот же, но варианты ответа или порядок букв другие (SC-003).
3. Второй раунд не начинается, пока это слово не отвечено верно (SC-004).
4. Довести занятие до конца: в «Словаре» у этого слова статус «Изучается»,
   срок — сегодня, счётчик забываний вырос (SC-006); у остальных слов срок в будущем.

### Сценарий 3 — прерванное занятие (FR-017a, SC-009)

1. Начать занятие, ответить на пару карточек первого раунда и уйти со страницы.
2. Ожидается: в «Словаре» срок, `ease` и счётчик забываний этих слов не изменились.
3. На странице «Статистика» число ответов за сегодня выросло — попытки в журнале остались.
4. Открыть «Повторение» снова: те же слова предлагаются заново, с первого раунда.

### Сценарий 4 — режим «Изучение» не задет (FR-018)

1. Открыть «Учить слова» и пройти занятие целиком.
2. Ожидается: карточка знакомства, шаги «выбор → буквы → аудирование», возврат слова
   в очередь через три карточки, «Уже знаю» добирает замену — всё как раньше.

## Проверка контракта вручную

```bash
curl -s "http://localhost:${UVICORN_PORT:-8000}/api/study/session?mode=review" | jq '{session_id, rounds: [.rounds[].exercise]}'
# ожидается: ["choice_ru_en","choice_en_ru","letters","dictation"]

curl -s -X POST "http://localhost:${UVICORN_PORT:-8000}/api/study/review/finish" \
  -H 'Content-Type: application/json' -d '{"session_id":"<id>"}' | jq
```
