# Implementation Plan: Вкладка «Настройки» с выбором голоса

**Branch**: `002-settings-voice-tab` | **Date**: 2026-08-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-settings-voice-tab/spec.md`

## Summary

В навигацию добавляется пятая вкладка «Настройки» со страницей выбора голоса озвучки.
Список показывает **все** английские голоса браузера, сгруппированные по языковому
варианту (🇺🇸 американский, 🇬🇧 британский, …), а первым пунктом идёт «Системный
голос» — именованное состояние «выбор не сделан», к которому можно вернуться. Щелчок
по голосу сохраняет выбор на устройстве и сразу произносит им образец.

Технически это правка одного только фронтенда: сервер, схема и контракт API не
меняются. Половина механики уже есть — `SpeechProvider` хранит выбранный голос в
`localStorage` под ключом `speech.voice` и применяет его в занятии и словаре, — но
интерфейса выбора нет, и провайдер к полному списку не готов: он режет голоса до
девяти (`MAX_VOICES`), раздаёт им эмодзи-аватарки по индексу и подменяет «выбор не
сделан» первым голосом списка (`chosen ?? voices[0]`).

Поэтому работа делится на три части: (1) провайдер отдаёт полный список,
сгруппированный по языку, честный `selected` (null = системный голос), метод
предпросмотра `speakWith` и текст последней ошибки озвучки; (2) новая страница
`SettingsPage` с маршрутом и пунктом навигации; (3) удаление мёртвого
`VoicePicker.tsx` — компонента на девять слотов с эмодзи, который не отрисовывается
нигде и противоречит новому списку.

## Technical Context

**Language/Version**: TypeScript 5 (strict), Node ≥ 22.12 (`.nvmrc`). Бэкенд не затрагивается.

**Primary Dependencies**: React 19, react-router, Tailwind 4, Vite. Новых зависимостей нет.

**Storage**: `localStorage`, ключ `speech.voice` (идентификатор голоса или `null`).
База данных и её схема не затрагиваются — миграции нет.

**Testing**: на фронтенде тест-раннера нет; ворота — `yarn typecheck` и `yarn build`
(Принцип III). `yarn test:api` и `ruff check` запускаются как регрессия: они должны
остаться зелёными, хотя бэкенд не меняется.

**Target Platform**: локальный однопользовательский веб-стенд (`yarn dev`), десктопный
браузер с Web Speech API (Chrome, Safari, Firefox)

**Project Type**: веб-приложение; в этой фиче — только `frontend/`

**Performance Goals**: страница настроек открывается мгновенно (данных с сервера не
запрашивает); образец звучит в течение 1 секунды после щелчка (SC-004); голос нужного
варианта находится в списке из нескольких десятков за ≤ 10 секунд (SC-007)

**Constraints**: озвучка остаётся на клиенте, серверная генерация речи запрещена
(Принцип V); настройка не уходит на сервер и не трогает прогресс, `review_log`,
`ease` (Принципы I, IV); список голосов приходит асинхронно и может быть пустым
(FR-010, FR-009); тексты интерфейса — на русском, идентификаторы — на английском

**Scale/Scope**: до нескольких десятков голосов в списке; 5 файлов фронтенда —
`speech/SpeechProvider.tsx` (правка), `pages/SettingsPage.tsx` (новый),
`App.tsx` (маршрут + навигация), `components/VoicePicker.tsx` (удаление),
`README.md` (правка). Бэкенд — 0 файлов.

**Structure Decision**: изменения целиком во фронтенде и повторяют сложившееся
разделение: страница-маршрут лежит в `frontend/src/pages/`, знание о синтезе речи
остаётся в единственном месте — `frontend/src/speech/SpeechProvider.tsx`. Страница
настроек не обращается к `window.speechSynthesis` напрямую: всё, что ей нужно —
список групп, текущий выбор, предпросмотр и текст ошибки — она получает из
контекста. Это сохраняет свойство, ради которого провайдер и заведён: обход
особенностей браузеров (асинхронный `voiceschanged`, разблокировка после жеста,
подвисшая очередь) живёт в одном файле, а не расползается по страницам.
