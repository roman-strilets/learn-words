# Phase 1 — Quickstart: проверка вкладки «Настройки»

Автотестов у фичи нет (фронтенд, тест-раннера в проекте нет — см. research.md, п. 8),
поэтому проверка состоит из ворот и ручного сценария. Сценарий короткий: он покрывает
все критерии успеха из спецификации.

## Предусловия

```bash
yarn setup      # если проект ещё не установлен
yarn dev        # поднимает бэкенд и фронтенд
```

В словаре должно быть хотя бы одно слово в обороте — иначе занятие не запустится и
шаги 3–4 проверить будет не на чем.

Браузер — Chrome или Safari на macOS: там английских голосов обычно несколько десятков,
и группировка видна по-настоящему. Звук в системе и во вкладке не должен быть заглушен.

## Ворота (обязательны перед коммитом)

```bash
yarn typecheck                                  # tsc -b, строгий режим
yarn build                                      # сборка Vite
yarn test:api                                   # регрессия: бэкенд не менялся
uv run --directory backend ruff check app tests # регрессия: Python не менялся
```

Все четыре обязаны пройти (Принцип III и раздел «Рабочий процесс»). Первые два —
собственно ворота фичи; вторые два должны остаться зелёными без изменений.

## Ручной сценарий

### 1. Вкладка на месте — FR-001

Открыть приложение. В навигации пять пунктов: Главная, Занятие, Словарь, Статистика,
**Настройки**. Щёлкнуть «Настройки» — открывается страница с разделом выбора голоса.

**Ожидается**: переход занимает одно действие с любой страницы (SC-001).

### 2. Список полный и сгруппированный — FR-002, FR-002a, FR-003a

Осмотреть список.

**Ожидается**:
- первым идёт пункт **«Системный голос»**, и он активен, если голос ещё не выбирался;
- дальше голоса разложены по вариантам с флагом и названием: 🇺🇸 Американский,
  🇬🇧 Британский, 🇦🇺 Австралийский и т. д.;
- голосов заметно больше девяти (на macOS — десятки). Если их ровно девять, старое
  ограничение `MAX_VOICES` не снято;
- основной голос браузера помечен, но остаётся в своей группе;
- найти британский голос удаётся за считаные секунды, не читая весь список (SC-007).

### 3. Выбор звучит сразу — FR-006, US2

Щёлкнуть по голосу из группы, отличной от текущей.

**Ожидается**: пункт становится активным, и **этот же** голос произносит образец в
течение секунды (SC-004). Частая ошибка реализации: слышен предыдущий голос — значит,
образец идёт через `speak()` по состоянию, а не через `speakWith()` (research.md, п. 3).

Щёлкнуть по нему же ещё раз — образец звучит снова (US2, сценарий 2).

### 4. Голос применился к занятию и словарю — FR-004

Не перезагружая страницу, перейти в «Занятие» и дойти до карточки с озвучкой
(`intro`, `choice_en_ru` или `dictation`). Затем открыть «Словарь» и нажать кнопку с
динамиком.

**Ожидается**: и там, и там звучит выбранный голос (SC-002). Перезагрузка не требуется.

### 5. Выбор переживает перезагрузку — FR-005

Обновить страницу (⌘R), вернуться в «Настройки».

**Ожидается**: активен тот же голос (SC-003). Закрыть и открыть браузер — результат тот же.

### 6. Возврат к системному голосу — FR-003a, US1 сценарий 5

Выбрать пункт «Системный голос».

**Ожидается**: он становится активным, звучит образец; в занятии слово произносит голос,
который браузер подобрал сам. В `localStorage` ключ `speech.voice` равен `null`:

```js
// в консоли браузера
localStorage.getItem('speech.voice')   // "null" после возврата к системному
```

### 7. Исчезнувший голос не ломает список — FR-008

Подделать ситуацию «голос удалён из системы»: в консоли браузера подставить
несуществующий идентификатор и перезагрузить страницу.

```js
localStorage.setItem('speech.voice', JSON.stringify('urn:voice:does-not-exist'))
location.reload()
```

**Ожидается**: страница настроек показывает активным «Системный голос» (а не пустоту и
не чужой голос), занятие продолжает звучать системным голосом — тишины нет (SC-005).

### 8. Отказ голоса объяснён — US2 сценарий 3

Воспроизводится не везде: нужен голос, который молчит. Надёжнее всего — сетевой голос
Google в Chrome при выключенной сети (Network → Offline в DevTools).

**Ожидается**: вместо молчания на странице появляется сообщение о том, что голос
недоступен, и можно выбрать другой. В консоли сообщение тоже остаётся, но пользователь
не обязан туда смотреть.

### 9. Пустой список и отсутствие синтеза — FR-009, US3

Проверяется в браузере без английских голосов; при отсутствии такого окружения —
временно вернуть из загрузчика голосов пустой массив.

**Ожидается**: вместо пустого списка — объяснение, что голоса не найдены и что
устанавливает их операционная система; пункт «Системный голос» остаётся. Если синтеза
нет вовсе (`supported === false`) — сообщение о том, что озвучка в этом браузере
недоступна, без списка.

### 10. Догрузка голосов — FR-010

В Chrome список голосов приходит асинхронно. Открыть «Настройки» первым же действием
после `yarn dev` (холодная загрузка) — если список сначала пуст, он **сам** заполняется
через мгновение, без перезагрузки страницы.

## Чего проверять не нужно

- **Прогресс и расписание** (FR-011): фича не делает запросов к API. Достаточно убедиться
  по вкладке Network, что при выборе голоса запросов на бэкенд не уходит.
- **Скорость речи и автоозвучка**: остались без интерфейса намеренно (Clarifications,
  вопрос 1). Их поведение не должно измениться — карточки озвучиваются так же, как до фичи.
