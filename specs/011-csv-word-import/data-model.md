# Data Model: Импорт слов из CSV

Схема базы не меняется: миграции нет. Импорт работает с существующими `words`,
`labels`, `word_labels` и не касается `progress` и журналов ответов. Новые
сущности живут только в памяти одного запроса.

## Существующие сущности, которые трогает импорт

### Word (`words`)

| Поле | Как меняет импорт |
|---|---|
| `word` | задаётся только у новой записи (из файла, `strip`) |
| `word_key` | `word_key_for(word)` — по нему ищется существующее слово |
| `translation` | новая запись — из файла; существующая — `merge_translation` дописывает через «; » значение, которого ещё нет |
| `example`, `example_translation` | заполняются только если `example` пуст, оба сразу |
| `created_at` | новая запись — `utcnow()` |
| `priority` | не меняется (новая запись — значение по умолчанию) |
| `labels` | добавляются метки строки; существующие не снимаются |

Связь `progress` у новой записи не создаётся: так слово остаётся «Новым», как
после ручного добавления.

### Label (`labels`)

Находится по `name_key = label_key(name)`, а если её нет, создаётся с написанием из
файла (`resolve_labels`). Существующая метка сохраняет своё написание и описание.

## Сущности в памяти (`app/word_import.py`)

### ImportRow

Одна принятая строка файла после проверки.

| Поле | Тип | Правило |
|---|---|---|
| `line` | int | номер строки как в табличном редакторе: заголовок 1, первая запись 2 |
| `word` | str | непустое, ≤ 128 символов |
| `translation` | str | непустое |
| `example` | str \| None | пустое → `None` |
| `example_translation` | str \| None | `None`, если нет `example` |
| `labels` | list[str] | ячейка разбита по «;», `strip`, пустые убраны, каждая ≤ 50 символов |

### SkippedRow

| Поле | Тип | Правило |
|---|---|---|
| `line` | int | как у `ImportRow` |
| `reason` | str | «нет слова», «нет перевода», «слово длиннее 128 символов», «метка «…» длиннее 50 символов» |

Строка, где все ячейки пустые, не становится ни `ImportRow`, ни `SkippedRow`.

### ParsedImport

Результат `parse_import(content: bytes)`.

| Поле | Тип |
|---|---|
| `rows` | list[ImportRow] — в порядке файла |
| `skipped` | list[SkippedRow] |
| `ignored_columns` | list[str] — исходные названия нераспознанных колонок |
| `total_rows` | int — непустые строки данных (`rows` + `skipped`) |

### ImportFileError

Исключение уровня файла: импорт не начинается, роутер отвечает кодом из исключения.

| Ситуация | Код | `detail` |
|---|---|---|
| файл больше `import_max_bytes` | 413 | «Файл больше 5 МБ» |
| в файле нет даже заголовка (пустой или только пробелы) | 422 | «Файл пустой» |
| не UTF-8 | 422 | «Файл не в UTF-8 — сохраните его как «CSV UTF-8»» |
| нет `слово` или `перевод` | 422 | «Нет обязательных колонок: перевод. Ожидаются: слово, перевод, пример, перевод примера, метка» |
| одно поле названо дважды | 422 | «Колонка «перевод» встречается дважды» |

### ImportReport (ответ API)

| Поле | Тип | Смысл |
|---|---|---|
| `rows` | int | прочитано непустых строк данных (`parsed.total_rows`) |
| `created` | int | строки, которые завели новую запись |
| `merged` | int | строки, которые что-то дописали в уже существующую запись (перевод, пример, метку) |
| `unchanged` | int | строки, после которых запись осталась как была |
| `skipped` | int | строки, пропущенные с причиной (`len(parsed.skipped)`) |
| `skipped_rows` | list[SkippedRow] | первые `import_skipped_report_max` пропусков |
| `labels_created` | list[str] | названия созданных меток по алфавиту |
| `ignored_columns` | list[str] | нераспознанные колонки |

Инвариант: `rows == created + merged + unchanged + skipped`. Все счётчики считают
строки файла, а не записи словаря: две строки, дописавшие одну запись, дают
`merged == 2`. Каждая строка попадает ровно в одну категорию. Если строка дописала что-то в запись,
которую раньше в этом же файле создала другая строка, она считается `merged`.

## Исход одной строки

```text
ImportRow
  ├─ word_key не встречался          → новая запись                         → created
  └─ есть записи с этим word_key
       запись = row_for_translation(записи, translation)
       ├─ перевод, пример или метки изменились → merged
       └─ ничего не изменилось                 → unchanged
```

`row_for_translation` выбирает запись, где перевод из файла уже есть, а если такой
нет, первую запись слова. Новые записи в этом же запросе сразу попадают в индекс,
поэтому повторы слова внутри файла сливаются по тем же правилам.
