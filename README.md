# Learn Words

Веб-приложение для изучения английских слов и фраз с интервальными повторениями.
Словарь и прогресс лежат в SQLite, озвучка работает на клиенте через Web Speech API.

- **Бэкенд** — Python 3.12+, FastAPI, SQLAlchemy 2.0, Alembic. Зависимости — `uv`.
- **Фронтенд** — React 19, TypeScript, Vite, TanStack Query, Tailwind 4. Зависимости — `yarn`.
- Монорепа: yarn workspaces для фронта, отдельный uv-проект для бэка.

## Требования

| Инструмент | Версия |
|---|---|
| Node.js | ≥ 22.12 (в репозитории `.nvmrc`) |
| uv | ≥ 0.11 |
| Python | ≥ 3.12 (поставит `uv`) |
| Ollama | необязательно — только для автоматической разметки, модель `nimble` |

Системный Node может быть старее — перед работой переключитесь:

```bash
nvm use          # прочитает .nvmrc
```

## Установка

```bash
yarn setup
```

Команда делает четыре шага: `uv sync`, `yarn install`, применение миграций и импорт
`dictionary.csv` (7271 уникальное слово). Импорт идемпотентен — повторный запуск
не создаёт дублей.

Пошагово, если нужно по отдельности:

```bash
uv sync --directory backend      # окружение Python
yarn install                     # окружение Node
yarn db:upgrade                  # миграции Alembic
yarn db:import                   # словарь из dictionary.csv
```

Автоматической разметке словаря нужна языковая модель. По умолчанию это
локальная [Ollama](https://ollama.com) на `http://localhost:11434` с моделью
`nimble`:

```bash
ollama pull nimble
curl -s localhost:11434/api/tags   # в списке должна быть nimble:latest
```

Без неё всё остальное работает как обычно — недоступна только кнопка
«Разметить автоматически», она ответит понятной ошибкой.

## Запуск

```bash
yarn dev
```

- Фронтенд — http://localhost:5173
- API — http://localhost:8000, документация — http://localhost:8000/docs

Vite проксирует `/api` на бэкенд, поэтому фронт ходит по относительным путям.

Порты живут в корневом `.env` — он общий для фронта и бэка и создаётся из
`.env.example` при первом `yarn dev`. Поменяйте их там, если дефолтные заняты
другим приложением:

```dotenv
UVICORN_PORT=8000   # API
WEB_PORT=5173       # фронтенд, туда же смотрит прокси /api
```

## Как устроено обучение

### Два вида занятия

С главной запускаются два занятия, каждое — на 5 слов своей категории:

| Кнопка | Что берёт | Чем заканчивается |
|---|---|---|
| **Учить слова** | 5 новых слов, которых ещё нет в изучении | Знакомство со всеми словами, затем пять раундов по типам упражнений |
| **Повторить слова** | 5 слов в обороте с подошедшим сроком, самые просроченные первыми | Пять раундов по типам упражнений, в конце — одно обновление расписания на слово |

Кнопка «Уже знаю» на карточке знакомства выводит слово из оборота и добирает
взамен следующее новое: занятие всё равно даёт 5 слов на изучение. Замена не
повторяет уже показанные слова — фронт присылает их список в `exclude_ids`.

Третья кнопка в блоке «Слова» — **Учить группу** — занятие по словам одной
метки вне расписания, см. «Занятие по группе».

### Знакомство с новыми словами

Занятие «Учить слова» начинается со знакомства: карточка со словом, переводом,
примером и озвучкой, на ней «Уже знаю» или «Изучить». Знакомство проходит по
всем словам занятия сразу — упражнений в это время нет.

Когда знакомство закончено, состав занятия окончателен («Уже знаю» до этого
момента выводит слово и добирает замену), и фронт одним запросом
`POST /api/study/rounds` получает план: те же пять раундов, что и в повторении.

Ошибка в изучении расписанием не наказывается: слово изучается впервые, забыть
его было нельзя, а ошибка тут же закрывается верным ответом в том же раунде.
Цена ошибки — лишняя карточка внутри занятия, не более. Этим изучение и
отличается от повторения, где любая ошибка означает «забыто».

### Порядок новых слов

На вкладке «Настройки» выбирается, в каком порядке «Учить слова» берёт новые
слова:

| Вариант | Какие слова приходят на знакомство |
|---|---|
| «В порядке добавления» (по умолчанию) | Самые давно добавленные, от старого к новому |
| «Сначала недавно добавленные» | Самые свежие, от нового к старому — удобно, пока помнишь, где встретил слово |

Слова, отмеченные в «Словаре» стрелкой «Учить первым», идут раньше всех
остальных при любом порядке (см. «Словарь»).

Порядок добавления — это порядок, в котором записи заводились в словарь; слова
одного импорта идут в порядке строк файла. Замена после «Уже знаю» берётся тем же
порядком. Выбор хранится на сервере, поэтому действует в любом браузере,
начиная со следующего занятия — уже начатое не перестраивается. На «Повторить
слова» порядок не влияет: там слова идут по сроку.

### Повторения (SM-2)

Пройдя занятие-изучение целиком, слово выпускается в режим повторений:
интервалы растут как `1 → 3 → interval × ease` дней, `ease` стартует с 2.5 и не опускается ниже 1.3.
К каждому сроку добавляется разброс ±10%, иначе слова одной сессии всплывали бы
одним днём.

Оценку качества (0–5) приложение выводит само, а не спрашивает у пользователя:

| Ситуация | Оценка |
|---|---|
| Верно с первой попытки, без подсказки | 5 |
| Верно, но нажимал подсказку | 4 |
| Верно со второй попытки | 3 |
| Ошибка | 2 |

Ошибка на повторении возвращает слово в изучение на шаг 1 и увеличивает
счётчик `lapses`. Такое слово поднимается на шаг за занятие: четыре занятия
до нового выпуска.

### Занятие идёт раундами

Занятие — что изучение, что повторение — это не очередь из случайных упражнений,
а пять раундов, по раунду на тип упражнения, в фиксированном порядке:

| Раунд | Упражнение | Что делает пользователь |
|---|---|---|
| 1 | `choice_ru_en` | По русскому переводу выбирает английское слово |
| 2 | `choice_en_ru` | По английскому слову выбирает перевод |
| 3 | `letters` | Собирает английское слово из перемешанных букв |
| 4 | `writing_ru_en` | Пишет английское слово по русскому переводу, без подсказок |
| 5 | `dictation` | Пишет слово, услышанное через синтез речи |

В раунде проходятся все слова занятия, и только потом начинается следующий.
Карточка-знакомство в раундах не встречается: в изучении она остаётся позади,
а в повторении слово и так знакомо.

Порядок слов в каждом раунде случайный и не повторяет порядок предыдущего раунда:
иначе слово запоминается по месту в очереди, а не по себе. Если слов три и больше,
раунд не начинается со слова, показанного последним, даже если последним был
повтор после ошибки. При двух словах так не выйдет, и раунды просто чередуют
два порядка.

Неверный ответ возвращает слово в конец текущего раунда с карточкой того же
типа, собранной заново — другие варианты ответа, другой порядок букв. Повторов
не ограничиваем: раунд закончится, когда на все его карточки ответят верно.

В упражнении с буквами порядок строгий: буква не на своё место не встаёт, банк
дёргается в ответ на промах. Поэтому серверу уходит не «неверно», а число
промахов — с ними ответ засчитывается как со второй попытки (качество 3 вместо
5). Провалить упражнение по-прежнему можно кнопкой «Показать ответ». Ради
проверки позиций карточка получает само слово в поле `solution` — так же, как
диктант получает его для озвучки; ответ всё равно проверяет сервер.

Горячие клавиши работают в любой раскладке: обработчики сопоставляются сначала по
`event.key`, а затем по `event.code` — по позиции клавиши. Английское слово в
упражнении с буквами можно набирать, не переключаясь с русской раскладки.

Расписание внутри занятия не двигается вовсе — ни в том режиме, ни в другом:
ответы только проверяются и попадают в `review_log` под ключом занятия
(`session_id`). Один раз, на `POST /api/study/finish`, сервер разбирает журнал
занятия и пересчитывает расписание каждого слова, прошедшего все пять раундов.
Иначе безошибочное занятие умножало бы интервал на `ease` пять раз подряд.

Итог занятия сервер выводит по-разному, и режим приходит в `finish` полем `mode`:

| Режим | Итог слова, прошедшего все пять раундов |
|---|---|
| `review` | По худшей попытке: любая ошибка, даже исправленная в том же раунде, откатывает слово в изучение, поднимает `lapses` и ставит срок «сегодня» |
| `learn` | Выпуск в повторения независимо от ошибок: интервал 1 день, `ease` и `lapses` не меняются |

Занятие, прерванное до конца раундов, расписание не меняет: незавершённые слова
остаются с прежним сроком, а их попытки — в журнале. Слово, брошенное посреди
занятия-изучения, останется в изучении и придёт в занятие «Повторить слова».

### Подбор вариантов ответа

Дистракторы не случайны: кандидаты набираются по общему началу и окончанию слова,
ранжируются расстоянием Левенштейна и фильтруются по переводу — два варианта с
одинаковым переводом сделали бы задание нерешаемым. Для `scrutiny` получается
`screenplay / scramble / scratch`.

### Несколько значений у одного слова

Слово можно завести несколько раз — по записи на каждое значение (`roll out` —
«вылезать» и «внедрить»). Записи учатся независимо: у каждой свой прогресс и свой
срок повторения. Уникальна пара слово + перевод, поэтому уже заведённое значение
повторно не добавить — форма отвечает 409. В варианты ответа идёт только одна
запись слова, иначе в карточке оказались бы две одинаковые кнопки.

Импорт CSV — и `yarn db:import`, и «Импорт из CSV» на «Словаре» — отдельных записей
под значения не заводит: новое значение он дописывает через `;` в ту запись слова,
где это значение уже есть, а если такой нет — в первую. Записи, заведённые
вручную, он не удаляет, не дробит и не перезаписывает.

### Словарь

Строка словаря живёт целиком на странице «Словарь»: слово можно прослушать,
поправить и перевести в другой статус, не заходя на отдельную страницу.

| Действие | Что делает |
|---|---|
| Кнопка с динамиком | Произносит слово выбранным голосом |
| Стрелка вверх | «Учить первым»: слово придёт в «Учить слова» раньше остальных новых |
| «Изменить» | Разворачивает строку в форму: слово, перевод, пример, его перевод и метки |
| Список статусов | Переводит слово в выбранный статус |

Под словом в строке видны его метки. В самой строке они только показываются,
поменять их можно в «Изменить» (см. «Метки»).

Правка проверяется тем же правилом, что и добавление: свести запись к значению,
которое уже заведено отдельной строкой, нельзя — форма отвечает 409 и введённое
остаётся на месте.

Смена статуса — не ответ на упражнение: `review_log` она не трогает, ease и
lapses остаются прежними. Меняется только то, без чего статус не имеет смысла:

| Статус | Что происходит |
|---|---|
| «Новое» | Прогресс удаляется, слово снова попадёт в занятие «Учить слова» |
| «Изучается» | Слово возвращается в изучение на нулевой шаг и доступно сразу |
| «На повторении» | Слово со своим расписанием возвращается к прежнему сроку, слово без расписания выпускается так же, как после занятия-изучения |
| «Знаю», «Отложено» | Слово уходит из оборота, расписание замирает — возврат в «На повторении» поднимет прежний срок |

Возврат в «Новое» стирает накопленное расписание, поэтому спрашивает
подтверждение — как удаление.

Стрелка «Учить первым» есть только у новых слов. Отмеченное слово стоит в
очереди «Учить слова» раньше всех неотмеченных, а среди отмеченных действует тот
же порядок, что выбран в «Настройках». Дневной лимит отметка не обходит.
Когда слово уходит в изучение — «Изучить», «Уже знаю» или смена статуса, — отметка
снимается сама; вернувшееся в «Новое» слово приходит без неё. Фильтр
«Учить первыми» оставляет в списке только отмеченные слова и сочетается с
поиском и статусным фильтром. Как и смена статуса, отметка не считается ответом
и в `review_log` не попадает.

Список «Все метки» рядом с фильтрами оставляет слова с одной выбранной меткой,
а пункт «Без меток» — слова, у которых меток нет. Фильтр по метке сочетается с
поиском, статусом и «Учить первыми». Если выбранную метку удалили, фильтр
возвращается к «Все метки».

#### Автоматическая разметка

Кнопка «Разметить автоматически» рядом с фильтрами открывает над списком панель
разметки. «Запустить» проходит все слова под текущими фильтрами «Словаря» и
просит языковую модель выбрать каждому **одну** подходящую метку из всех меток —
или ни одной, если ни одна не подходит (`bicycle` при метках «кухня», «тело»,
«растения» останется без метки). Модель видит слово вместе с переводом, поэтому
различает значения: `bark` «кора» и `bark` «лаять» — две разные записи.

- Метки только добавляются: те, что уже стоят на слове, не снимаются, а уже
  стоявшая выбранная метка не считается новой. Повторный запуск ничего не меняет.
- Прогресс, расписание и `review_log` не меняются — это правка словаря, а не
  ответ на упражнение. Лишнюю метку можно снять в «Изменить».
- Слова идут пачками по 20 — по одному запросу к модели на пачку. После каждой
  пачки обновляются прогресс «обработано X из Y» и сам список: новые метки видны
  сразу.
- Итог — сколько слов обработано, сколько получили каждую метку и сколько
  остались без новой метки.
- Если модель недоступна или не ответила за 120 секунд, разметка
  останавливается с причиной. Уже размеченные пачки остаются на словах; пачка,
  на которой случилась ошибка, не применяется ни частично.

Без меток запускать нечего — панель предложит завести их на вкладке «Метки».

Словарь большой, а локальная модель неторопливая, поэтому работу можно резать
на этапы. Перед запуском в панели настраивается:

| Поле | Что делает |
|---|---|
| Метки | Чипы всех меток, включены все. Выключенная модели не предлагается и не ставится |
| Не больше, слов | Ограничивает этап; пусто — вся выборка под фильтрами |
| Размер пачки | Сколько слов в одном запросе к модели, от 1 до 100, по умолчанию 20 |
| Начать с | С начала, с места остановки прошлого этапа или с выбранного поиском слова |

Слова обходятся в порядке «Словаря» (по порядку добавления), и под кнопкой
«Запустить» видно, сколько слов попадёт в этап. Фильтры «Словаря» действуют и
здесь: «Без меток» + «Изучаются» значат то же, что в списке.

«Остановить» дожидается конца текущей пачки — она применяется целиком — и
показывает «Продолжить с «…»» со словом, на котором этап остановился. Та же
кнопка появляется после ошибки модели. Размер пачки, лимит и место остановки
запоминаются в браузере: после перезагрузки панель предложит продолжить
оттуда, где остановилась. Место остановки стирается, когда выборка пройдена до
конца.

#### Импорт из CSV

Кнопка «Импорт из CSV» рядом с фильтрами открывает над списком панель импорта
(одновременно открыта только одна панель — импорт или разметка). Выберите файл и
нажмите «Импортировать»: новые слова появятся в списке со статусом «Новое», с
метками из файла, без перезагрузки страницы.

Первая строка файла — заголовок. Колонки узнаются по названию, в любом порядке,
без учёта регистра, крайних пробелов и «ё»:

| Поле | Названия колонки |
|---|---|
| слово (обязательная) | `слово`, `word` |
| перевод (обязательная) | `перевод`, `translation` |
| пример | `пример`, `пример использования`, `example` |
| перевод примера | `перевод примера`, `example_translation` |
| метки | `метка`, `метки`, `label`, `labels` |

Английские названия — как в `dictionary.csv`, поэтому его тоже можно загрузить
отсюда без правок. Разделитель колонок «,» или «;» определяется по заголовку:
табличные редакторы в русской локали сохраняют CSV через «;». Кодировка — UTF-8
с BOM или без («CSV UTF-8» в меню сохранения); файл в Windows-1251 отклоняется с
подсказкой.

```csv
слово;перевод;пример;перевод примера;метка
saucepan;кастрюля;Put the saucepan on the stove.;Поставь кастрюлю на плиту.;Кухня
whisk;венчик;;;"Кухня; Посуда"
```

Несколько меток — в одной ячейке через «;». Если «;» разделяет и колонки, ячейку
берут в кавычки, как у `whisk`. Метки, которых ещё нет, создаются; «кухня»
совпадает с существующей «Кухня» и берёт её написание.

Слияние — по тем же правилам, что у `yarn db:import`, чтобы оба способа давали
одинаковый словарь:

- слово ищется так же, как при ручном добавлении: регистр и пробелы по краям не
  различаются;
- та же пара слово + перевод новой записи не заводит;
- новый перевод дописывается через «;» в запись, где это значение уже есть, а
  если такой нет — в первую запись слова (`кастрюля` → `кастрюля; сотейник`);
- пример с переводом подставляется только в запись без примера;
- метки добавляются, уже стоящие не снимаются;
- несколько строк одного слова в файле сливаются по тем же правилам.

Прогресс, отметка «Учить первым» и журналы ответов не меняются: импорт — правка
словаря, а не ответ на упражнение. Повторный импорт того же файла ничего не
меняет. Слова одного импорта считаются добавленными в порядке строк файла, так
что «В порядке добавления» учит их в том же порядке. Фразы импорт не трогает.

После импорта панель показывает отчёт: сколько строк прочитано, сколько из них
добавили слово, дополнили запись, ничего не изменили или пропущены; какие метки
созданы и какие колонки не распознаны. Пропущенная строка указана с номером, как
в табличном редакторе, и причиной: «нет слова», «нет перевода», «слово длиннее
128 символов», «метка «…» длиннее 50 символов» (пределы — как у ручной формы).
Пустые строки пропускаются молча. Поимённо перечисляются первые 200 пропусков.

Файл без колонки слова или перевода, с одной колонкой дважды, пустой, не в UTF-8
или больше 5 МБ отклоняется целиком с причиной. Импорт применяется целиком или
никак: сбой посреди файла оставляет словарь прежним.

### Метки

Метка — тематическая пометка слова: «кухня», «глаголы движения», «из сериала».
У слова может быть сколько угодно меток, у метки — сколько угодно слов.

Метки ставятся в форме слова — и при добавлении, и в «Изменить» в словаре. Поле
«Метки» по мере ввода подсказывает существующие метки; если такой ещё нет,
последним пунктом идёт «Создать метку «…»». Enter выбирает первый пункт,
крестик на метке снимает её. Метки сохраняются вместе со словом: новая метка
появляется только при сохранении, поэтому «Отмена» или отклонённая правка
(слово-дубль, 409) новых меток не оставляет.

Регистр не различается: «Кухня» и «кухня» — одна метка, и выбранная по
подсказке метка сохраняет своё написание. Метки упорядочены по алфавиту, «ё»
стоит вместе с «е».

Общий список меток — на вкладке «Настройки → Метки» (`/settings?tab=labels`):
у каждой метки число слов. Здесь метку можно завести заранее, переименовать —
новое название сразу видно у всех её слов — или удалить. Удаление спрашивает
подтверждение с числом слов и снимает метку со всех слов сразу; сами слова и
их прогресс остаются.

У метки может быть описание для автоматической разметки — короткое пояснение
темы, до 200 символов. Модель видит его вместо названия: «B2» она поймёт хуже,
чем «advanced vocabulary (CEFR B2)». Описание задаётся при создании метки и в
«Изменить» на вкладке «Метки» и показывается под её названием; пустое поле —
описания нет, разметка судит по названию.

Метки — ручная разметка словаря. На занятия они не влияют: «Учить слова» и
«Повторить слова» берут те же слова, что и без меток. Правка меток, как и смена
статуса, не считается ответом и в `review_log` не попадает. Консольный
`yarn db:import` меток не трогает, а «Импорт из CSV» на «Словаре» их ставит и
недостающие создаёт (см. «Импорт из CSV»).

### Озвучка

Слова произносит браузер, звук не скачивается с сервера. Голос выбирается на
вкладке «Настройки»: список показывает все английские голоса системы,
разложенные по варианту языка — 🇺🇸 американский, 🇬🇧 британский,
🇦🇺 австралийский и так далее. Щелчок по голосу сразу произносит им короткий
образец, поэтому выбирать можно на слух, а не по имени.

Первым пунктом идёт «Системный голос» — это состояние «выбор не сделан»: голос
подбирает сам браузер по языку. К нему можно вернуться в любой момент, и он же
становится активным, если выбранный голос исчез из системы, — тогда озвучка
продолжает работать, а не замолкает.

Выбор запоминается в браузере (он не уходит на сервер и не влияет на прогресс) и
действует сразу и в занятии, и в словаре: кнопка с динамиком в словаре произносит
слово тем же голосом. Сами голоса устанавливает операционная система — если
нужного варианта в списке нет, добавить его можно только в её настройках.

### Фразы

Фразы — вторая колода: «break the ice», «once in a blue moon», «It's up to you.».
У них свой раздел «Фразы» (`/phrases`), свои метки и свои занятия «Учить фразы»
и «Повторить фразы». Со словами фразы не пересекаются: фраза не видна в
«Словаре», не попадает в занятия со словами и в варианты ответа к словам, а
слово — к фразам. Одна и та же строка может быть и словом, и фразой.

Всё остальное устроено как у слов: список с поиском, фильтрами статуса,
«Учить первой» и метками; добавление, правка, ручная смена статуса и удаление с
подтверждением; озвучка кнопкой с динамиком; знакомство с «Уже знаю» и добором
следующей фразы, пять раундов тех же упражнений, расписание SM-2, пересчитанное
один раз в конце занятия. На главной и в «Статистике» у фраз свой блок; числа
слов и фраз не суммируются.

Чем фразы отличаются от слов:

- **Длина** — до 200 символов вместо 128.
- **Апостроф при проверке не важен.** «It's up to you.», «Its up to you» и
  «IT’S up-to you!» — один и тот же ответ. Остальные правила общие: регистр,
  лишние пробелы, дефисы и знаки препинания не важны, а состав и порядок слов
  проверяются строго: «it is up to you» и «up to you it's» не засчитываются.
- **Порядок новых** — всегда по добавлению (отмеченные «Учить первой» — раньше);
  настройка «Порядок новых слов» на фразы не действует.
- **Свои лимиты** — `NEW_PHRASES_PER_SESSION`, `REVIEW_PHRASES_PER_SESSION`,
  `DAILY_NEW_PHRASES_LIMIT` (см. «Настройки»): занятие с фразами не тратит
  дневной лимит новых слов, и наоборот.
- **Свои метки** — на вкладке «Настройки → Метки фраз»
  (`/settings?tab=phrase-labels`). Метка фраз может называться так же, как метка
  слов: это разные метки. Автоматической разметки у фраз нет.
- **Сборка из букв** — как у слов: пробелы, апострофы и знаки препинания стоят
  на своих местах, собираются только буквы. «It's up to you!» — маска
  `__'_ __ __ ___!` и 10 букв в банке.
- **Варианты ответа** берутся только из фраз. Пока фраз меньше четырёх,
  вариантов в карточке выбора столько, сколько фраз, — правильный есть всегда.

Хранятся фразы в своих таблицах: `phrases`, `phrase_progress`,
`phrase_review_log`, `phrase_labels`, `phrase_label_links`. Ответы по фразам
пишутся в `phrase_review_log`, статистика фраз строится из него.

### Занятие по группе

«Учить группу» на главной (`/study/group`) — занятие по словам одной метки,
например перед поездкой прогнать всё из «Аэропорта». Список показывает все
метки слов по алфавиту: сколько в группе слов, номер круга и «пройдено X из N».
«Учить» у метки запускает занятие; у метки без слов вместо кнопки — «нет слов».

- **Слова любого статуса.** В группу входят все слова с этой меткой: новые, в
  изучении, на повторении, «Знаю» и отложенные.
- **Без знакомства.** Занятие сразу идёт теми же пятью раундами, что
  «Повторить слова»: выбор рус → англ, выбор англ → рус, сборка из букв,
  написание, аудирование. Ошибка возвращает карточку в конец раунда, как обычно.
- **Порция** — `GROUP_WORDS_PER_SESSION` слов (по умолчанию 5); группа меньше
  порции даёт все свои слова. Дневных лимитов нет: занятие по группе можно
  проходить сколько угодно раз подряд, и лимит новых слов оно не тратит.
- **По кругу.** Порции идут по всей группе без повторов: каждая берёт следующие
  непройденные слова круга. Слово пройдено в круге, когда ответило верно во всех
  пяти раундах занятия, — ошибки по дороге не мешают; слово, не дошедшее до конца
  раундов, остаётся непройденным. Когда круг пройден, следующее занятие начинает
  новый круг в **другом порядке**: при трёх словах и больше он не начинается со
  слова, которым кончился прошлый, а два слова меняются местами.
- **Добор на стыке.** Если в круге осталось меньше слов, чем порция, она
  добирается первыми словами следующего круга — без слов остатка: в одной порции
  слово бывает только раз. Добранные слова после занятия считаются пройденными
  уже в следующем круге.
- **Прерванное занятие.** Место в круге хранится на сервере для каждой метки —
  переживает перезагрузку и другой браузер. Занятие, брошенное на середине,
  при следующем запуске даёт те же слова (порядок в раундах — новый).
- **Изменения меток.** Слово, получившее метку посреди круга, встаёт в конец
  текущего круга. Слово, с которого метку сняли, выпадает из группы и из
  текущего занятия; вернут метку — вернётся и его место в круге. Переименование
  метки круг не сбрасывает, удаление метки удаляет и её круги.
- **«Начать круг заново»** — у группы, где уже что-то пройдено: следующее
  занятие начнёт новый круг в новом порядке. Подтверждения нет — прогресс слов
  это не стирает.
- **Не влияет на основное обучение.** Статусы, расписание, «Учить первым»,
  составы «Учить слова» и «Повторить слова» и вся «Статистика» от занятия по
  группе не меняются: оно не пишет ни `progress`, ни `review_log`.
- **Варианты ответа** в карточках выбора — из всего словаря, а не только из
  группы.

Хранится занятие по группе в своих таблицах: `group_cycle_words` — место
каждого слова в круге метки и отметка прохождения, `group_review_log` — журнал
ответов занятий по группе. Метки фраз в группы не попадают.

```

POST   /api/phrases                   добавить фразу (409 на то же значение)
GET    /api/phrases/{id}
PATCH  /api/phrases/{id}
PUT    /api/phrases/{id}/status
PUT    /api/phrases/{id}/priority     {priority} — «Учить первой» (409 не новой фразе)
DELETE /api/phrases/{id}

POST   /api/phrase-labels             без /classify: разметки фраз нет

GET    /api/phrase-stats/daily?days=30
```

Правила те же, что у слов, с отличиями из «Фраз»: текст фразы 1–200 символов
(иначе 422), `from_id` не поддерживается, `labels` — названия меток **фраз**,
дубль — 409 «Фраза «…» с переводом «…» уже есть в словаре», 404 — «Фраза не
найдена». `session_id` занятия со словами, переданный в
`/api/phrase-study/finish`, — пустой список, и наоборот: журналы разные.

`GET /api/settings/classifier` отдаёт действующее подключение к модели;
`is_default` — `true`, пока ничего не сохранено. `PUT` сохраняет три значения
разом: адрес — `http://` или `https://` до 512 символов, ключ — до 512 печатных
ASCII-символов без пробелов, модель — до 128 символов; поля обрезаются по
краям, пустое или неверное — 422. `DELETE` удаляет сохранённое и отдаёт
значения по умолчанию. `POST /api/settings/classifier/check` с теми же полями
задаёт модели один вопрос с таймаутом 15 секунд и отвечает 200 и при неудаче:
`{ok: false, detail: "Модель «nimbel» не найдена"}`.

`new_words_order` принимает `oldest_first` (по умолчанию, пока настройку не
меняли) или `newest_first`; другое значение или пропущенное поле — 422. Порядок
действует на все три точки отбора новых слов: `GET /api/study/session?mode=learn`,
замену в `POST /api/study/select` и `GET /api/study/new`. Смена настройки
в `review_log` не попадает.

Новые слова во всех трёх точках отбираются так: сначала слова с `priority`,
затем остальные, внутри каждой группы — по `new_words_order`. У слова поле
`priority` есть всегда; поставить `true` можно только слову без прогресса,
иначе 409, а `false` принимается всегда. «Изучить», «Уже знаю» и
`PUT /api/words/{id}/status` с любым статусом, кроме `new`, снимают отметку.
`GET /api/words?priority=true` оставляет только отмеченные слова и сочетается
с `search` и `status`.

У слова всегда есть поле `labels` — список `{id, name}` по названию без учёта
регистра, «ё» = «е»; у слова без меток `[]`. `POST /api/words` и
`PATCH /api/words/{id}` принимают `labels` — список **названий**: существующие
метки находятся без учёта регистра и сохраняют своё написание, недостающие
создаются в той же транзакции, что и слово, повторы схлопываются. В `PATCH`
отсутствие поля не меняет метки, `[]` снимает все; 409 откатывает и правку, и
новые метки. Пустое название или длиннее 50 символов — 422.

`GET /api/words?label=<id>` оставляет слова с этой меткой, `label=none` — слова
без меток; фильтр сочетается с `search`, `status` и `priority`. Неизвестный `id`
— пустая страница, а не 404; другое значение — 422.

`GET /api/words?from_id=<id>` оставляет только записи с `id ≥ from_id` и
сочетается с остальными фильтрами; `from_id` меньше 1 — 422. Это курсор
разметки: панель по нему считает слова этапа (`total` при `limit=1`) и находит
слово, с которого продолжить.

`GET /api/labels` отдаёт `{id, name, description, word_count}` по алфавиту,
`word_count` у метки без слов — 0, `description` без описания — `null`.
`POST /api/labels` принимает `{name, description?}`. `PATCH /api/labels/{id}` —
частичная правка: меняются только переданные поля, поэтому `{name}` по-прежнему
только переименовывает, а `{description: null}` или `""` стирает описание; тело
без полей — 422. Название — те же правила: 422 на пустое или длиннее 50
символов, 409, если название без учёта регистра занято другой меткой. Смена
только регистра своего же названия — не конфликт. Описание обрезается по краям,
пустое становится `null`, длиннее 200 символов — 422. `DELETE /api/labels/{id}` снимает метку со всех слов, а слова,
прогресс и `review_log` не трогает. Метки не влияют ни на один маршрут `/study`.

`POST /api/labels/classify` размечает одну пачку. Тело — фильтры `search`,
`status`, `priority`, `label` (те же, что у `GET /api/words`), `label_ids` —
набор меток, `from_id` — курсор (нет — с начала) и `limit` — размер пачки от 1
до 100. Сервер берёт до `limit` подходящих записей с `id ≥ from_id` по
возрастанию `id`, спрашивает модель и ставит каждой выбранную метку, если её ещё
нет. Ответ — `{results, skipped, next_from_id, remaining}`: в `results` по
записи `{word_id, word, translation, label, added}` на каждое слово (`label` —
`null`, если ни одна не подошла; `added` — метка поставлена этим запросом),
`skipped` — слова, удалённые, пока модель думала, `next_from_id` — курсор
следующей пачки или `null`, если слов дальше нет, `remaining` — сколько их
осталось. Сервер этап не помнит: фронт повторяет запрос с `next_from_id`.

Метки из `label_ids`, которых уже нет, пропускаются; если не осталось ни одной —
422 «Нет меток для разметки». Пустая выборка — 200 с пустым `results`, модель
не вызывается. Когда виноват не запрос, а модель, коды другие: 502 — сервис
недоступен, отклонил ключ, не знает модель или ответил не по схеме; 504 — не
ответил за 120 секунд. В обоих случаях `detail` называет причину, и ни одна
метка пачки не поставлена.

Ответы проверяются на сервере: это единый источник правды и полный `review_log`
для статистики. Сравнение мягкое — регистр, лишние пробелы, дефисы и ведущие
`to`/`a`/`the` игнорируются, поэтому «out-of-town» и «out of town» равнозначны.

Ответ занятия-повторения содержит `session_id` и `rounds` — по раунду на каждый
из пяти типов упражнений, в каждом по упражнению на каждое слово занятия.
В режиме `learn` `rounds` пуст: состав занятия известен только после знакомства,
поэтому план приходит отдельным `POST /api/study/rounds`. Слово, выведенное из
оборота между знакомством и этим запросом, молча пропускается, а пустой
`word_ids` — не ошибка, а пустой список раундов.

Порядок `exercises` в раундах перемешан, и клиент не должен полагаться на его
стабильность: два запроса с теми же словами могут вернуть разный порядок.
Для плана из `n` слов сервер гарантирует:

- в каждом раунде по карточке на каждое слово, без потерь и дублей;
- порядок первого раунда случайный, он не повторяет ни словарь, ни `word_ids`,
  ни «самые просроченные первыми»;
- при `n ≥ 2` порядок каждого следующего раунда отличается от предыдущего;
- при `n ≥ 3` следующий раунд не начинается со слова, которым закончился предыдущий.

Если занятие отошло от плана (повтор после ошибки в конце раунда, выбывшее
слово), клиент на границе раунда переставляет следующий раунд по тем же
правилам, но состав раунда не меняет.

`POST /api/study/answer` принимает `mode` (по умолчанию `learn`) и `session_id`,
обязательный в обоих режимах (иначе 422): без ключа занятия попытку некуда
записать. Ответ проверяется и пишется в журнал, но расписание не трогает,
а после ошибки в `next_exercise` приходит карточка того же типа, собранная
заново.

Карточка `writing_ru_en` содержит только `word_id` и `prompt` (русский перевод):
ответа в ней нет, и до проверки он в браузер не уходит. Подсказки у неё тоже нет,
поэтому `used_hint` для этого упражнения сервер игнорирует и оценку не снижает.

`POST /api/study/finish` отдаёт список слов, прошедших все пять раундов, с их
новым расписанием. Оценку выводит сервер из журнала занятия, а не клиент; `mode`
решает, как её применить (см. «Занятие идёт раундами»). Повторный вызов с тем же
`session_id` ничего не пересчитывает второй раз, а неизвестный `session_id` —
не ошибка, а пустой список.

Занятие по группе: `done` — сколько слов пройдено в текущем круге, `cycle` —
его номер, 0 — по группе ещё не занимались; `done == word_count` — круг пройден,
следующее занятие начнёт новый. `GET /groups` ничего не создаёт, а
`POST /session` заводит строки круга, поэтому он `POST`; повтор без `finish`
даёт тот же набор слов. В группе нет слов — `session_id` равен `null`, `rounds`
пустые. Ответ на `/answer` — поля ответа обычного занятия без `progress`;
`exercise: "intro"` — 422, слово без этой метки — 409 «Слова больше нет в
группе», нет слова или метки — 404. `/finish` возвращает слова, верно ответившие
во всех раундах, и отмечает их пройденными; повтор с тем же ключом ничего не
меняет и возвращает тот же список, неизвестный ключ — пустой список.

Очередь сессии живёт на фронте, бэкенд остаётся stateless: перезагрузка страницы
просто пересобирает сессию из актуального прогресса. `session_id` серверного
состояния не создаёт — это колонка журнала, по которой попытки одного занятия
находят друг друга.

## Настройки

Значения по умолчанию — в `backend/app/config.py`, переопределяются через
`backend/.env` (образец в `backend/.env.example`):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `NEW_WORDS_PER_SESSION` | 5 | Сколько новых слов даёт занятие «Учить слова» |
| `REVIEW_WORDS_PER_SESSION` | 5 | Сколько слов даёт занятие «Повторить слова» |
| `DAILY_NEW_LIMIT` | 20 | Дневной лимит новых слов |
| `NEW_PHRASES_PER_SESSION` | 5 | Сколько новых фраз даёт занятие «Учить фразы» |
| `REVIEW_PHRASES_PER_SESSION` | 5 | Сколько фраз даёт занятие «Повторить фразы» |
| `DAILY_NEW_PHRASES_LIMIT` | 20 | Дневной лимит новых фраз — отдельно от слов |
| `GROUP_WORDS_PER_SESSION` | 5 | Сколько слов даёт одно занятие «Учить группу»; дневного лимита нет |
| `IMPORT_MAX_BYTES` | 5000000 | Предел размера файла «Импорта из CSV»; больше — 413 |
| `IMPORT_SKIPPED_REPORT_MAX` | 200 | Сколько пропущенных строк импорта отчёт перечисляет поимённо |

Порядок новых слов здесь не настраивается: он меняется из интерфейса, на вкладке
«Настройки → Общие», и хранится в базе (см. «Порядок новых слов»). Там же, на
вкладке «Метки», — общий список меток (см. «Метки»), а на вкладке «Метки фраз» —
метки фраз (см. «Фразы»).

Подключение к модели для автоматической разметки настраивается на вкладке
«Настройки → Разметка» (`/settings?tab=classifier`) и хранится в базе:

| Поле | По умолчанию | Смысл |
|---|---|---|
| Адрес сервиса | `http://localhost:11434` | Куда ходить за моделью, `http://` или `https://` |
| Ключ доступа | `ollama` | Ollama ключ не проверяет, но поле не может быть пустым |
| Модель | `nimble` | Имя модели на сервисе |

«Сохранить» запоминает все три значения разом и подключение не проверяет —
сохранить настройки выключенного сейчас сервиса можно. «Проверить подключение»
задаёт модели один короткий вопрос с введёнными в поля, ещё не сохранёнными
значениями и показывает «Модель отвечает» или причину («Модель «nimbel» не
найдена», «Сервис разметки недоступен по адресу …»). «Сбросить» забывает
сохранённое и возвращает значения по умолчанию.

Ключ лежит в `backend/data/app.db` открытым текстом. База в репозиторий не
попадает, но ключ облачного сервиса с деньгами на счету туда лучше не класть.

Значения по умолчанию, таймауты и предел пачки — в `backend/app/config.py`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `CLASSIFIER_BASE_URL`, `CLASSIFIER_API_KEY`, `CLASSIFIER_MODEL` | см. выше | Подключение, пока на вкладке ничего не сохранено |
| `CLASSIFIER_TIMEOUT_SECONDS` | 120 | Сколько ждать ответа на одну пачку |
| `CLASSIFIER_CHECK_TIMEOUT_SECONDS` | 15 | Сколько ждать «Проверить подключение» |
| `CLASSIFIER_BATCH_MAX` | 100 | Наибольший размер пачки |

Переменные `TYPESAFE_*` из примеров `typesafe-sdk` приложение не читает:
адрес, ключ и модель передаются клиенту явно и перебивают окружение.

## Что не сделано

- Голосовой ввод (Web Speech Recognition) — озвучка есть, распознавание нет.
- Упражнение на подстановку слова в пример: данные есть у 91% записей.
- Повторение по расписанию только для слов одной метки: «Учить группу» идёт
  вне расписания.
- Занятие по метке фраз.
- Статистика занятий по группе: ответы копятся в `group_review_log`, но нигде
  не показываются.
- Автоматическая разметка ставит слову не больше одной метки за прогон; несколько
  подходящих меток сразу она не выбирает.
- Отмена прогона одной кнопкой: «Остановить» дожидается конца текущей пачки,
  а снять поставленные прогоном метки можно только вручную.
- Порог уверенности модели: метка ставится, даже если модель сомневалась, —
  отказаться она может только вариантом «ни одна».
- Разметка при добавлении слова и при импорте CSV — сейчас только кнопкой на
  «Словаре».
- Импорт фраз из CSV: `yarn db:import` и «Импорт из CSV» заводят только слова,
  фразы — вручную.
- Автоматическая разметка фраз: метки фраз ставятся только вручную.
- Порядок новых фраз: всегда по добавлению, отдельной настройки нет.
- Сборка фразы из слов (вместо сборки из букв).
- Авторизация: приложение однопользовательское, прогресс лежит в отдельной
  таблице, поэтому `user_id` добавляется без перестройки схемы.
